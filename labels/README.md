# 자가 라벨 (self-labeling)

대회 규칙 2-2·2-3에 따라 자가 라벨링은 허용되며, 라벨 생성 코드·절차·모델 기록을 보존한다.

## train250_audit.csv

무라벨 20,000건(`open/train_unlabeled.jsonl.gz`)에서 뽑은 250건 표본에 대해, 파이프라인이 **위반으로 판정한 (공고, 항목) 쌍**이 실제 위반인지 검토한 라벨이다. 실제 분포에서의 정밀도를 재고 오탐 패턴을 찾는 데 쓴다. 제출 파이프라인의 규칙·모델 입력에는 들어가지 않는다.

| 열 | 뜻 |
|---|---|
| id | 무라벨 공고 ID |
| item | 항목 (v1~v24) |
| label | 1 = 위반, 0 = 위반 아님 |
| confidence | high / medium / low |
| reason | 판단 근거 요약 |

### 생성 절차

1. 표본: `open/train_unlabeled.jsonl.gz`의 줄을 `random.Random(20260917).shuffle` 후 앞 250건 → `runs/mlx/train_sample250.jsonl`.
2. 판정: `scripts/mlx_eval_extract.py --generate-only`로 로컬 MLX(`mlx-community/gemma-4-26b-a4b-it-4bit`) 추출 출력을 만들고, 후보 `script.py`의 판정기로 판정.
3. 검토 자료: `scripts/audit_unlabeled.py`가 판정 쌍마다 메타·품목 판별·근거 문구·관련 원문 줄을 출력.
4. 라벨: 검토 자료와 원문, 법령패키지(판로지원법·시행령, 지방·국가계약법 시행규칙, 중기부 고시 CSV)와 dev 라벨 관례를 대조해 판단.
   - 라벨 작성: Claude Opus 5 (`claude-opus-5`), Claude Code 세션(2026-09-17). 입력은 대회 제공 자료만 사용했고 웹 검색·외부 문서는 쓰지 않았다.
   - dev 관례를 따른 판단: 일반경쟁 입찰은 v16·v18 대상 아님, SW사업자 업종 요구 사업은 v20 대상(하드웨어 임차 포함), 본문에 없고 메타에만 있는 지역제한은 확신도 low로 위반 처리.
5. 집계: `python scripts/audit_unlabeled.py --sample ... --labels labels/train250_audit.csv --report`.
