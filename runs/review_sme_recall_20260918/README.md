# sme_recall 제출 전 리뷰 — 2026-09-18

기존 후보와 ZIP은 수정하지 않았다. 검증용 실험 코드만 이 디렉터리에 저장했다.

## 결론

현재 후보의 dev 0.8344753694와 기존 평가 스크립트의 교차선택 평균 0.8058을 재현했다.
ZIP의 소스 일치 및 독립 mock 실행도 통과했다. 작은 판정 수정으로 dev 0.8365587027을 확인했지만 서버 점수 상승은 아직 검증하지 않았다.

## 발견 사항

### P1. 모든 모델 호출에 실패해도 정상 제출처럼 종료한다

`script.py:588–600`의 `run_chunk`는 건 단위 재시도까지 실패하면 빈 문자열을 반환한다.
`run`은 이를 정규식으로 처리하고 CSV 형식만 맞으면 PASS를 반환한다. 모든 호출에서 예외를 던지는 러너로 test 1건을 실행했는데도 `자가검증: PASS`였다(`failed_runner_report.json`).

공식 규칙은 공고 내용으로 고정 LLM의 정상 응답을 최소 한 번 받도록 요구한다.
https://dacon.io/competitions/official/236754/overview/rules (리뷰 시 확인)

개선: 공고별 정상 호출 성공 여부를 JSON 파싱 여부와 별도로 기록하고, 실패 공고는 더 짧은 프롬프트로 재시도한다. 본·보조 호출 모두 실패한 공고가 남으면 성공으로 보고하지 않는다. 이 실행 경로 변경은 아래 판정 실험 패치에는 포함하지 않았다.

### P2. 다른 법령의 제2조의3도 우선조달 예외로 인식한다

`script.py:825–850`은 조문 번호만으로 예외를 인정한다.
무라벨 `PPS-D-020711`에 있는 “인지세법 시행령 제2조의3”이 실제로 이 조건에 걸렸다. 이 공고는 추정가격 148,968,222원, 일반경쟁, 완전관측이며 메타 예외 문구도 없다. 해당 인지세 조문을 이유로 v16을 제외하는 것은 잘못된 예외 식별이다. 다만 무라벨 공고이므로 최종 정답이 1이라고 확정한 것은 아니다.

실험 수정: 조문 번호 일치에는 주변 120자의 판로지원·구매촉진·우선조달 문맥을 요구했다. dev·250건 판정 불변, 500건에서는 이 공고의 v16만 0→1. 주변 창 방식이라 인접한 별도 문장이 섞일 가능성은 남는다. 최종적으로는 법령명과 해당 조문을 같은 인용 구간에서 연결하는 편이 더 정확하다.

### P2. 명시적인 우선조달 대상 문구를 참가자격으로 놓친다

`script.py:752–754`의 자격 문장 필터에 “우선조달계약 대상”이 없다.
dev `PPS-DEV-173`의 참가자격 2번은 “우선조달계약 대상으로 '소기업' 또는 … '소상공인'”인데 `rx_sme_level`은 없음으로 판단해 v18을 오탐한다.

실험 수정: 자격 문장 조건에 `우선\s*조달계약\s*대상`을 추가했다.
dev에서는 이 오탐 1건만 제거됐고, 무라벨 250+500건의 모든 판정은 불변이었다.

### P2. 첨부 탈락 정보가 최종 부재 판정에 반영되지 않는다

`dropped_doc_counts`는 프롬프트에만 들어가며 `judge`에는 제약이 없다. 특히 정규식을 사용하는 v16·v18·v20에는 LLM이 이 정보를 읽어도 직접적인 효과가 없다.
dev에서 탈락 첨부가 있는 부재 양성은 5쌍, 무라벨 500건에서도 5쌍이었다(`probe_results.json`의 `dropped_absence`). 이 모두가 오탐이라는 의미는 아니다.

개선: 빠진 문서 유형이 해당 요구사항을 담을 수 있는지, 남은 공고에 자격 요건이 충분히 명시됐는지 구분해야 한다. 탈락이 있으면 무조건 0으로 바꾸는 패치는 권하지 않는다. 별도 검토가 필요하므로 실험 수정에 포함하지 않았다.

## 예외 해석에서 조심할 점

- `meta_exception`은 “협상에 의한 계약”만으로 면제한다. 배포 시행령 제2조의3 제1항 제4호는 특정 성능·기술·품질 및 우선조달로 목적 달성이 불가능한 상황을 요구하며, 해당 메타 문자열만으로 충족된다는 근거는 확인되지 않았다. 이 조건을 단순 삭제하면 dev 0.8322, 무라벨 500건에서는 8쌍이 추가된다. 미확정 해석이므로 내일 즉시 삭제하는 것은 권하지 않는다.
- `judge`의 주석은 예외를 부재형에만 적용한다고 하지만 본문 `exception`은 v14·v15·v17도 막는다. 이를 일괄 해제하면 DEV-113 v17 오탐이 추가되어 dev 0.8322로 내려간다. 본문·메타 예외의 범위 차이를 명시하고, 재공고 확대·법정 예외를 각각 판단해야 한다.
- 교차검증 코드는 전체 dev를 보고 만든 정규식은 고정한 채 사실 출처(rx/llm/or/and)만 반씩 나눠 선택한다. 규칙 개발 전체가 독립 검증된 수치가 아니다. 무라벨 500건도 이전 오탐 검토와 이번 리뷰에 사용됐으므로 완전히 손대지 않은 검증셋으로 부르기 어렵다.
- README의 Public 0.67~0.72는 검증된 예측구간이 아니다. 이 리뷰에서는 Public 점수를 추정하지 않았다.
