### 실행 안전성 점검 (2026-09-18)

서버에서 한 건이라도 예외가 나면 2시간과 그날 제출권을 잃는다. 이번에 추가한 코드가 `rec["docs"][0]`에 접근하므로 확인했다.

| 확인 | 결과 |
|---|---|

2. 수정 9의 `협상에 의한 계약`을 예외로 보는 해석은 시행령 제2조의3 ①4호의 **추정**이다. dev v16·v18 양성 13건에는 이 값이 하나도 없고 음성에만 나타나므로 일관되지만, 운영진이 확인한 규칙은 아니다.

4. **SW 제48조형의 판단 축은 여전히 미해결.** 운영진은 사업금액 구간으로 v10~v13 / v20을 가른다고 했으나(35행) 기준 금액 필드가 미답변이다. 우리 게이트는 `is_software()`를 쓴다.
5. v10은 dev 0.462로 올랐지만 여전히 최악이다. 남은 놓침 4건은 모두 품목 식별 실패("해당없음")이고, 전용 품목 호출의 답을 그대로 쓰면 오탐이 더 늘어 프롬프트 변경이 필요하다.
6. 수정 12의 조건 대조는 낱말 일치라 거칠다. "Clock 3.2GHz 이하"처럼 수치 조건을 실제로 비교하지는 않는다.
7. **v1(0.667)은 프롬프트를 바꿔야 한다.** 놓침 3건(DEV-046·063·072)은 운영진이 짚은 "법령상 근거 없는 **시설·인력 보유 제한**" 유형인데([토크 게시판 정리](../../docs/01_competition/05_talkboard_findings.md) 27행이 DEV-046·063을 위반 사례로 명시), 우리 추출 프롬프트는 "특정 기관·단체만 참가" 여부만 묻는다. 반대로 오탐 DEV-101("DEWESOFT를 사용한 소음 계측 기술을 보유한 업체나 기관으로 제한")은 **같은 형태인데 라벨이 0**이다. 운영진 말대로 "과업상 필요성·관련성"까지 따져야 갈리므로 정규식으로는 구분할 수 없다.

규칙을 눈으로 고치는 작업은 여기서 수확 체감이다. 남은 dev 오류는 항목당 1~3건이고, 오늘 성과는 전부 **법 조문에서 예외를 찾고 그것이 어느 필드에 기록되는지 확인**하는 데서 나왔지 오답을 하나씩 고쳐서 나온 게 아니다. 남은 셋은 성격이 다르다.
