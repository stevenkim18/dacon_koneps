판정기만 바뀌었다. LLM 호출·프롬프트·출력 예산은 A와 같다(예상 서버 시간 약 51분).

## 왜 ①은 남겼나

- dev 5월 묶음(무편집 공고) 오탐 26건 중 **v9가 9건**으로 가장 많다. 다른 항목은 0~2건이다(int8, A 기준). ①은 이 9건을 3건으로 줄이고 위반 묶음 정탐 1건(DEV-09)을 잃는다.
- ①이 지우는 5월 묶음 v9 적중 6건은 모두 모델·형식명 줄이다(DEV-110 "형식명 : PKBXL03.8C5D(V3800-CR-TI-DW29)", DEV-148 "GPU: NVIDIA RTX Pro 4000 Blackwell 24GB GDDR7", DEV-176 "(모델 WKA-167 )", DEV-088 "베터리(BDC70)" 등). 라벨은 모두 0이다. 남는 3건은 읽지 않았다. 위반 묶음 DEV-09는 "Chipset: GB10 Grace Blackwell Superchip"로 **같은 종류의 줄**인데 라벨이 1이다. 원문 내용이 아니라 편집 여부가 라벨을 가른다는 가장 직접적인 dev 증거다.
- ①은 모델명 전용 호출과 본 호출이 **둘 다** 특정 모델 지정이라고 읽을 때만 인정한다. 메타 필드로 판단 대상을 거르지 않으므로 운영 답변과 부딪치지 않는다.

## ③ 수정 — B의 v22 정규식 구멍 4개

B가 무라벨 20,000에 새로 켠 v22 34건을 전부 읽었다. 법상 참석 제한으로 읽히는 것이 약 17~19건이고, 약 10건은 분명한 오탐이다. 그중 규칙으로 막을 수 있는 구멍을 고쳤다.
