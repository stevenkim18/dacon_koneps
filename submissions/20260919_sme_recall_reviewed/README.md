## 점수 판단: 전달률이 0.32에서 0.57로 올랐다

제출 전 예측은 **0.666~0.683(중심 0.675)**이었고 실제는 0.6716800657로 구간 안에 들어왔다.
경쟁하던 두 예측 모델은 **둘 다 빗나갔다** — 2점 직선(전달률 0.318)은 0.666으로 낮게, 저장소의 `Public ≈ 교차검증 - 0.126`은 0.682로 높게 예측했다.

| 후보 | 교차검증 | dev 200 | Public | 교차검증-Public | 구간 전달률 |
|---|---:|---:|---:|---:|---:|
| rule_extract | 0.6774 | 0.7203 | 0.6247556727 | +0.0526 | — |
| sme_level | 0.7849 | 0.8174 | 0.65888921 | +0.1260 | 0.318 |
| **sme_recall_reviewed** | **0.8075** | **0.8366** | **0.6716800657** | +0.1358 | **0.566** |

**이번 구간의 전달률은 0.566으로 직전 구간(0.318)의 약 1.8배다.** 두 구간의 차이는 개선을 어디서 찾았는지다.

- sme_level 세대: dev 오답을 열어 보고 고친 수정 → 전달률 0.318 (study log가 스스로 진단한 "dev 과적합")
- sme_recall·reviewed 세대: 법령패키지를 읽고 찾은 수정 + 무라벨 전수 검증 → 전달률 **0.566**

세 점을 모두 쓴 회귀는 `Public ≈ 0.3471 x 교차검증 + 0.3892`이고 세 점 모두 잔차 ±0.003으로 맞는다.
다만 이 기울기는 성격이 다른 두 구간의 평균이므로, 법령 기반 작업에는 0.566을 쓰는 편이 실제에 가깝다.

`Public ≈ 교차검증 - 0.126`은 폐기한다. 차이가 -0.053 → -0.126 → **-0.136**으로 계속 벌어지는 것은 상수 오프셋이 아니라 기울기 < 1인 직선의 모습이다.
