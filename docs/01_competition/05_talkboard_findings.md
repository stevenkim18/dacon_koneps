> 범위: [대회 토크 게시판](https://dacon.io/competitions/official/236754/talkboard) 3쪽의 공지·질문·표시된 댓글; 9월 23일 [v20 답변](https://dacon.io/competitions/official/236754/talkboard/417849)과 [신규 복합 질문](https://dacon.io/competitions/official/236754/talkboard/417940)

## 먼저 적용할 결론

1. **24개 항목을 모두 예측한다.** 평가 데이터에는 모든 항목의 양성 사례가 있으며, 점수는 항목별 위반 클래스 F1의 단순 평균이다. 어떤 항목을 전부 0으로 내면 그 항목 F1은 0이다. [운영 답변](https://dacon.io/competitions/official/236754/talkboard/417197)
2. **dev 라벨을 암기하지 않는다.** dev 200건은 판정 유형을 보여 주는 예시이고 실제 평가 분포를 대표하지 않는다. 일부 라벨은 제공 자료로 재현되지 않는다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195) · [라벨 검증 답변](https://dacon.io/competitions/official/236754/talkboard/417272) · [PPS-DEV-062 정정](https://dacon.io/competitions/official/236754/talkboard/417699)
3. **공고문, 첨부문서, meta를 함께 본다.** 특히 부재탐지 항목은 관련 단어의 존재와 실제 입찰참가자격 요구를 구별해야 한다. [문서 범위 답변](https://dacon.io/competitions/official/236754/talkboard/417633) · [첨부문서 답변](https://dacon.io/competitions/official/236754/talkboard/417698)
4. **v10~v18은 대상 식별 → 세부품명 대조 → 특이사항 평가 순으로 판단한다.** 배포된 중기부 고시 CSV와 금액·계약방식 조건을 함께 써야 한다. [운영진 상세 답변](https://dacon.io/competitions/official/236754/talkboard/417282)
5. **v10·v11과 v20은 각각 독립 판정한다.** 운영진은 9월 3일 답변을 정정했다. 금액 구간으로 셋 중 하나만 고르는 배타적 분기를 만들면 안 된다. [정정 답변](https://dacon.io/competitions/official/236754/talkboard/417706)
6. **명백한 오탈자·띄어쓰기는 문맥 이해용으로 정규화할 수 있다.** 오타 자체는 위반이 아니며, 외부 원문을 찾아 복원하면 안 된다. 근거문구는 정규화 전 `docs.text`에 실제 존재하는 부분문자열을 그대로 제출한다. [오타 처리 답변](https://dacon.io/competitions/official/236754/talkboard/417766)
7. **제출 전 로컬 검증에 시간을 쓴다.** 제출은 하루 1회이고, 평가 데이터 1,853건을 2시간 안에 처리해야 한다. [제출 횟수 공지](https://dacon.io/competitions/official/236754/talkboard/417223) · [평가 건수 답변](https://dacon.io/competitions/official/236754/talkboard/417239)
8. **지방계약 v5~v7의 지역제한 기준금액은 발주기관·용역 종류에 따라 다르다.** 9월 22일 공지로 보완된 시·도(세종 제외) 물품·일반용역 3억 5천만 원을 포함해 아래 표로 판단한다. 공지 내용은 제출물에 사용 가능한 대회 제공 자료다. [보완 공지](https://dacon.io/competitions/official/236754/talkboard/417908)
9. **v20에서 `meta.정보화사업여부=미입력`은 비SW가 아니다.** 값이 등록되지 않았다는 뜻이다. 공고문·제공 첨부의 사업 내용을 배포 「소프트웨어 진흥법」 제2조와 대조해 SW 사업 여부를 판단하고, 제48조와 배포 지침으로 사업금액별 참여제한을 판단한다. [9월 23일 운영진 댓글](https://dacon.io/competitions/official/236754/talkboard/417849)

## 평가와 데이터의 의미

- 평가 데이터 1,853건 모두 dev·무라벨 train과 같은 레코드 스키마이며 **meta 21개 필드**가 있다. 본문에서 모든 meta 값을 다시 추출할 필요는 없다. 다만 v24에서는 공고서와 meta를 반드시 대조한다. [meta 답변](https://dacon.io/competitions/official/236754/talkboard/417317)
- 2시간 제한을 단순히 건수로 나누면 공고당 평균 약 **3.9초**다. 이는 모델 로딩·추론·결과 저장을 모두 포함한 거친 예산이며, 실제 설계에서는 초기화 시간과 긴 문서에 대한 여유가 필요하다. [평가 건수 답변](https://dacon.io/competitions/official/236754/talkboard/417239)
- `train_unlabeled` 20,000건에는 위반 공고가 섞여 있을 수 있어 정상 라벨로 일괄 취급하면 안 된다. 제공 자료의 자가 라벨링은 허용되며 검증셋, RAG 사례집, 후처리 규칙에 사용할 수 있다. 외부 LLM으로 라벨을 만들 때도 입력은 대회 제공 자료로 한정한다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)
- `dev_labels.csv`의 근거 열이 비어 있는 양성 사례가 있다. 이는 근거가 없다는 뜻이 아니다. 운영진은 PPS-DEV-062의 v24=1을 현재 배포 공고문·meta로 재현할 수 없으며 별도 예외로 해석할 필요가 없다고 명시했다. PPS-DEV-119의 v10·v11, PPS-DEV-193의 v13도 라벨보다 판정 기준을 우선할 여지가 언급됐다. [v1·v24 근거 답변](https://dacon.io/competitions/official/236754/talkboard/417321) · [라벨 데이터 답변](https://dacon.io/competitions/official/236754/talkboard/417282) · [v24 정정](https://dacon.io/competitions/official/236754/talkboard/417699)
- 리더보드에는 `v1~v24`만 반영된다. `e1~e24`는 2차 정성평가에 쓰이므로 본문에 있는 정확한 부분문자열을 500자 이하로 넣는다. 부재탐지 5개 항목(`e10`, `e11`, `e16`, `e18`, `e20`)은 빈칸이다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)

### 문서와 데이터 처리에서의 공통 주의점

- 공고문 외 첨부에서만 위반이나 자격 요건이 드러날 수 있다. 실제 레코드의 `docs`에 있는 문서를 읽는다. 문서명만 언급됐고 원문이 `docs`에 없는 표준 서식은 공고별 입력으로 보지 않는다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195) · [첨부문서 답변](https://dacon.io/competitions/official/236754/talkboard/417698)
- `dropped_doc_counts`가 비어 있지 않으면 첨부 일부가 빠진 상태다. 부재탐지 항목에서 ‘현재 문서에 없음’을 곧바로 위반으로 단정하면 틀릴 수 있다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)
- `null`과 `"미입력"`은 모두 ‘해당 없음’과 다르다. v24에서는 meta를 무조건 신뢰하거나 무시하지 않는다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)
- 오타 자체를 별도 위반으로 판정하는 항목은 없다. 띄어쓰기와 명백한 오탈자는 문맥 이해를 위해 내부 정규화할 수 있지만 외부 원문으로 복원·보충할 수 없다. 금액·지역·업종·자격처럼 판정에 직접 영향을 주는 값은 오타라고 임의 보정하지 말고 제공 원문과 문맥을 기준으로 판단한다. 평가 데이터에도 오타가 있을 수 있다. [오타 처리 답변](https://dacon.io/competitions/official/236754/talkboard/417766)
- `e1~e24` 근거는 전처리로 고친 문장이 아니라 제공된 `docs.text`에 실제 존재하는 부분문자열이어야 한다. 판정용 정규화 텍스트와 제출용 원문 위치를 따로 보존한다. [오타 처리 답변](https://dacon.io/competitions/official/236754/talkboard/417766)

## 제출·실행 관련 확정 사항

- 하루 제출은 **1회**이며 채점 완료가 아닌 **제출 시점**을 기준으로 센다. 대기열에 있는 제출도 1회에 포함된다. 2026-08-27의 리더보드 초기화와 제출 재개 이후 이 방식으로 운영된다. [변경 공지](https://dacon.io/competitions/official/236754/talkboard/417223) · [제출 시점 답변](https://dacon.io/competitions/official/236754/talkboard/417206)
- 제출 코드는 평가 공고마다 해당 공고 내용을 포함한 프롬프트로 **고정 LLM을 1회 이상 정상 호출**해야 한다. 미리 저장한 결과로 호출을 생략하거나, 다른 평가 공고의 정보·예측·통계를 재사용하는 캐시는 허용되지 않는다. 제공 자료로 만든 RAG 인덱스 같은 정적 자산과 공고 내부의 분할 추론은 허용된다. [캐시 답변](https://dacon.io/competitions/official/236754/talkboard/417337)
- 결과 CSV는 `id, v1~v24, e1~e24`의 49열이며, `v`는 정수 0/1, 누락·중복 ID 없이 입력 순서를 맞춘다. `e`는 위반일 때 원문 부분문자열, 비위반일 때 빈칸이다. [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)
- 서버는 인터넷이 차단된다. 모델뿐 아니라 토크나이저도 Hugging Face 모델 ID 대신 `PPS_MODEL_DIR`, `PPS_EMBED_DIR`의 로컬 경로로 읽는다. 데이터·출력도 `PPS_DATA_DIR`, `PPS_OUTPUT_DIR`을 사용한다. vLLM 실행 진입점은 `if __name__ == "__main__":` 아래에 둔다. [모델 경로 답변](https://dacon.io/competitions/official/236754/talkboard/417357) · [데이터 명세](https://dacon.io/competitions/official/236754/talkboard/417195)
- 예외를 잡아 메시지만 출력하고 종료하면 제출 화면에 실패 원인이 안 나올 수 있다. 실행 실패를 조사할 때 traceback이 드러나게 한다. [제출 오류 답변](https://dacon.io/competitions/official/236754/talkboard/417355)
- Mac의 MLX로 로컬 파이프라인을 검증해도 된다. 서버는 고정 Gemma 모델과 vLLM으로 채점하므로 로컬 출력·점수가 같다고 가정할 수 없다. 자체 Python 모듈은 제출 ZIP에 포함 가능하며, 코드 모듈은 `model/` 밖에 두는 것을 권장한다. [MLX 답변](https://dacon.io/competitions/official/236754/talkboard/417286) · [모듈 구성 답변](https://dacon.io/competitions/official/236754/talkboard/417214)
- 각 공고에서 고정 LLM을 정상 호출하면서 같은 호출의 0/1 토큰 logprob와 미리 정한 항목별 임계값으로 후처리할 수 있다. 임계값은 공개 dev 또는 허용된 자가 라벨로 조정할 수 있지만 제출 전에 고정해야 하며, 별도 분류기·회귀기의 학습 가중치는 허용되지 않는다. 상수는 `script.py`나 `model/` 아래 JSON 설정에 둘 수 있다. [logprob 답변](https://dacon.io/competitions/official/236754/talkboard/417746)

## 현재 프로젝트에서 권장하는 실험 순서

아래는 운영진의 지시가 아니라 위 답변과 프로젝트의 [dev 분석](../02_data/03_dev-200-analysis.md)을 연결한 **실험 제안**이다. 완료 여부는 별도 실행 기록으로 확인한다.

1. 현재 dev 예측의 **항목별 F1**과 실행 시간을 기준선으로 기록한다. 전체 평균뿐 아니라 24개 항목 각각의 양성 예측 수와 오탐·누락을 본다.
2. 공고문과 실제 `docs` 첨부를 항목별로 전달하고, `meta` 21개 필드·익명화 지역 토큰·`dropped_doc_counts`를 빠뜨리지 않는다.
3. v10~v18의 경쟁제품 분기를 배포 고시 CSV의 **명칭·특이사항**과 연결한다. SW 사업금액은 추정가격+부가가치세를 기본으로 하되 장기계속·분할발주 예외 산식을 구분하고, v10·v11·v20은 각각 독립 판정한다.
4. 부재탐지 5개 항목에서 ‘관련 단어 발견’과 ‘실제 참가자격 요구’를 구분한 뒤 dev 오답을 다시 확인한다.
5. 판정용 텍스트는 명백한 띄어쓰기·오탈자를 정규화할 수 있지만, `e` 근거를 만들 때는 원문 좌표로 돌아가 실제 `docs.text` 부분문자열을 사용한다.
6. 항목별 변경을 한 번에 하나씩 적용해 dev F1, 실행 시간, 근거 문자열 유효성을 비교한다. 마지막으로 전체 1,853건·2시간 제한과 제출 ZIP 형식을 검증한 뒤 하루 1회 제출을 사용한다.
