# 대회 안내 - 평가

> 출처: https://dacon.io/competitions/official/236754/overview/evaluation

## 1. 리더보드 산식

평가 산식은 Macro F1입니다.

24개 검토 항목 각각에 대해 위반(=1) 클래스의 F1 Score를 계산하고, 24개 항목의 F1을 단순 평균합니다.

24개 항목 전부가 채점 대상입니다. 평가 데이터는 24개 항목 모두에 위반(=1) 사례를 포함하므로, 특정 항목의 F1이 정의되지 않는 경우는 발생하지 않습니다.

- 위반 여부 열(v1~v24)만 리더보드 점수에 반영됩니다.
- 근거 문구 열(e1~e24)은 리더보드에 반영되지 않습니다.
- 제출 원본은 보존되어 2차 평가의 정성평가 재료로 사용됩니다.

| 구분 | 내용 |
|---|---|
| Public Score | 전체 테스트 데이터 1,853건 100% |
| Private Score | 대회 종료 시점의 Public Score |

## 2. 평가 기준

### 1차 평가

Private Score 기준 상위 15팀을 2차 평가 진출팀으로 선정합니다.

### 2차 평가

진출팀에 대해 아래 항목을 검증·평가하고, 정량 평가와 정성 평가를 종합하여 최종 수상팀을 선정합니다.

#### 1) 재현 검증

대회에서 제공한 자료와 제출 자료만으로 리더보드 점수가 재현되는지 검증합니다.

재현이 불가능한 경우 수상이 취소될 수 있습니다.

#### 2) 근거 문구 정성평가

정답이 위반(1)인 항목의 근거 문구(e1~e24)를 대상으로 정성평가를 진행합니다.

제공 원문의 부분문자열이 아닌 근거 문구(요약·수정·생성된 문구)는 자동 검증 단계에서 무효 처리됩니다.

대조 대상은 해당 공고에 제공된 본문 텍스트(공고문·첨부 문서)이며, 나라장터 등록 정보(메타데이터) 필드값은 대조 대상이 아닙니다.

근거 문구는 정답 근거와 일치하는 정도로 평가하므로, 위반에 해당하는 부분만 인용하는 것이 유리합니다.

부재탐지형 5개 항목은 “있어야 할 기재가 없는 것”이 위반이어서 인용할 원문이 존재하지 않으므로 정성평가 대상에서 제외됩니다.

- v10
- v11
- v16
- v18
- v20

#### 3) 규칙 준수 검증

대회 규칙 및 제출 요건(공고당 고정 모델 정상 호출 등)의 준수 여부를 검증합니다.

2차 평가의 진행 절차와 자료 제출 방법은 2차 평가 진출팀에 별도 안내됩니다.

## 3. 코드 제출 대회 가이드

본 대회는 submit.zip 파일을 제출하는 방식의 코드 제출 대회로 진행됩니다.

## 채점 대기시간 안내

제출한 코드를 평가 서버에서 직접 실행하여 채점합니다.

과제 특성상 추론 실행에 긴 시간이 소요되며 실행 제한시간은 2시간입니다. 제출이 몰리는 시간대에는 채점 대기열이 발생하여 결과 확인까지 수 시간이 소요될 수 있습니다.

- 제출 후 점수가 바로 표시되지 않는 것은 정상이며 오류가 아닙니다.
- 채점이 완료되면 리더보드에 점수가 반영됩니다.
- 대기열 상황에 따라 채점 소요 시간은 달라질 수 있습니다.
- 마감 직전에는 제출이 몰려 채점이 지연될 수 있으므로 여유를 두고 제출해야 합니다.

## 제출 파일 구조

submit.zip은 다음 구조로 구성합니다.

    submit.zip
    ├── script.py          # 필수 — 평가 서버에서 자동 실행되는 추론 코드
    ├── requirements.txt   # 선택 — 추가 설치가 필요한 패키지 명시
    └── model/             # 선택 — RAG 인덱스·설정 파일 등 정적 자산
                            # 학습된 모델 가중치 포함 불가

script.py는 제출 시 평가 서버에서 자동으로 실행됩니다.

제출 시 평가 서버가 script.py 파일 유효성 검사와 폴더 구조 정규화를 수행합니다. zip 최상위에 폴더가 한 겹 감싸진 경우 등 단순한 구조 차이는 정규화 과정에서 보정될 수 있으나, 가급적 위 구조 그대로 압축해야 합니다.

script.py가 확인되지 않는 제출물은 설치 오류로 처리됩니다.

requirements.txt와 model/ 폴더는 별도의 유효성 검사를 하지 않습니다. 내용에 오류가 있으면 설치 또는 실행 단계에서 오류로 나타납니다.

requirements.txt를 포함하는 경우 pip install -r requirements.txt 명령어로 설치 가능한 형태여야 합니다.

## 모델은 제출하지 않습니다

고정 LLM과 보조 임베딩 모델은 평가 서버에 미리 준비되어 있으며, script.py가 환경변수 경로(PPS_MODEL_DIR, PPS_EMBED_DIR)로 로드합니다.

제출물은 추론 코드만으로 구성해야 합니다. 학습된 모델 가중치를 zip에 포함하는 것은 허용되지 않으며, 용량 제한 초과의 원인이 될 수 있습니다.

model/ 폴더는 RAG 인덱스 등 정적 자산 전용입니다.

## 평가 서버에서 추가되는 항목

제출 시 평가 서버에서 submit.zip에 아래 항목이 자동으로 추가됩니다.

    submit.zip
    ├── script.py
    ├── requirements.txt
    ├── model/
    ├── data/                    # 평가 데이터 자동 마운트·읽기 전용
    └── output/submission.csv    # 결과 저장 경로

data/ 디렉토리는 데이터 탭에서 배포되는 data/ 폴더와 동일한 구성이며, test.jsonl.gz만 실제 평가 데이터인 무라벨 1,853건으로 교체됩니다.

data/는 읽기 전용이므로 쓰기 및 수정이 불가능합니다.

output/ 디렉토리에는 script.py 실행 결과가 반드시 submission.csv 파일명으로 저장되어야 합니다.

- 컬럼: 49열(id, v1~v24, e1~e24)
- 행 수: 입력 건수
- 인코딩: UTF-8, BOM 없음

## 제출 형식 검증

- v1~v24 값은 0 또는 1만 허용
- 확률값(0.73)이나 True/False, Y/N 표기는 불가
- 위반 여부 열에 빈 값이 없어야 함
- ID가 중복되면 안 됨
- 평가 데이터의 ID가 하나라도 누락되면 안 됨
- e1~e24는 리더보드 채점에는 사용하지 않음
- 위반이 아니거나 인용할 근거가 없는 항목은 빈 값
- 부재탐지형 e10, e11, e16, e18, e20은 항상 빈 값
- e1~e24 열 자체는 포함하여 49열로 저장

## 경로 계약

| 환경변수 | 내용 |
|---|---|
| PPS_DATA_DIR | 평가 데이터 디렉토리, 읽기 전용 |
| PPS_OUTPUT_DIR | 결과 저장 디렉토리 |
| PPS_MODEL_DIR | 고정 LLM 가중치 경로, 읽기 전용 |
| PPS_EMBED_DIR | 보조 임베딩 모델 가중치 경로, 읽기 전용 |

절대 경로를 하드코딩하지 말고 환경변수로 접근해야 합니다.

## 고정 모델

- 고정 LLM: google/gemma-4-26B-A4B-it
  - 리비전: 4d7ae4984b7db7de8f8457170b3f1a419ee76d52
  - 경로: PPS_MODEL_DIR
- 보조 임베딩 모델: BAAI/bge-m3
  - 리비전: 5617a9f61b028005a4858fdac845db406aefb181
  - 경로: PPS_EMBED_DIR

script.py는 vLLM offline API(from vllm import LLM)로 고정 모델을 직접 로드하여 추론합니다.

모델 컨텍스트 상한은 max_model_len 32,768이며, 베이스라인은 다음 설정을 사용합니다.

- quantization=int8_per_channel_weight_only
- max_model_len=16,384

고정 LLM이 GPU 메모리 대부분을 사용하므로 LLM과 임베딩 모델의 GPU 동시 로드는 보장되지 않습니다.

런타임에 Hugging Face 모델 ID로 다운로드를 시도하면 실패합니다. 반드시 PPS_MODEL_DIR과 PPS_EMBED_DIR의 로컬 경로를 사용해야 합니다.

## 유의사항

### 설치 오류

- submit.zip 내부 구조 불일치
- 패키지 설치 오류
- 일일 제출 횟수에 반영되지 않음

### 제출 오류

- script.py 실행 후 발생하는 오류
- 일일 제출 횟수에 반영됨

script.py의 실행 코드는 반드시 다음 가드 아래에 두어야 합니다.

    if __name__ == "__main__":
        ...

vLLM이 하위 프로세스를 spawn 방식으로 생성하므로, 모듈 최상위에서 LLM(...)을 생성하면 실패할 수 있습니다.

모델 출력을 JSON으로 안정적으로 받으려면 structured outputs를 권장합니다. 제출 형식 JSON 스키마는 data/정답스키마_디코딩.json으로 제공되며 베이스라인 코드에 사용 예가 있습니다.

로컬 개발 환경(GPU·런타임·정밀도)은 자유입니다. 로컬 실행 결과와 평가 서버 결과는 다를 수 있습니다.
