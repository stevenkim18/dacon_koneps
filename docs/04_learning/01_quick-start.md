# 먼저 해보는 대회 실습 계획

[학습 가이드로 돌아가기](README.md)

## 1. 목표와 진행 원칙

대회 기간 안에 공식 베이스라인을 실행하고, 점수를 측정하고, 근거가 있는 개선을 한 번 이상 해본다. 하루 2~3시간 기준의 제안이며 사용 가능한 시간과 실행 환경에 따라 조정한다.

1. 필요한 개념을 짧게 읽고 바로 실제 데이터에 적용한다.
2. 기본 입출력과 실제 모델 실행을 초반에 확인한다.
3. 처음 작동한 버전을 보존한다.
4. 변경은 한 번에 하나씩 하고 점수와 시간을 기록한다.
5. RAG·자가 라벨링 등 확장은 기본 평가가 가능해진 뒤 선택한다.

제출 마감은 **2026-09-29 10:00 KST**다. 대회 종료일인 9월 30일과 다르므로 9월 28일까지 제출 후보를 검증하고 제출하는 것을 목표로 한다. [공식 일정](https://dacon.io/competitions/official/236754/overview/schedule)

## 2. 지금 알아둘 최소 개념

| 개념 | 의미 | 여기서 확인할 것 |
|---|---|---|
| 샘플 | 데이터 한 건 | 공고 하나와 그 첨부·메타데이터 |
| 라벨 | 정답 표시 | 항목별 위반 0/1 |
| dev | 개발·검증용 예시 데이터 | 예측과 정답 비교 |
| 추론 | 모델로 결과를 계산하는 과정 | 공고에서 판단 결과 생성 |
| 프롬프트 | 모델에 제공하는 지시와 자료 | 판단 조건·문서·출력 형식 |
| 토큰 | 모델이 텍스트를 처리하는 단위 | 글자 수와 다르며 입력 길이에 영향 |
| 컨텍스트 | 모델이 이번 호출에서 참고할 내용 | 공고·첨부·관련 조문 |
| 구조화 출력 | 정해진 형식으로 답을 받는 방법 | JSON 형식이 맞아도 내용은 틀릴 수 있음 |
| RAG | 자료를 검색해 모델에 함께 주는 방식 | 필요한 법령을 찾아 제공 |
| 임베딩 | 문장을 비교 가능한 벡터로 표현 | 의미 기반 검색에 활용 |
| 정밀도 | 위반 예측 중 실제 위반 비율 | 정상 공고를 잘못 잡는지 |
| 재현율 | 실제 위반 중 찾아낸 비율 | 위반을 놓치는지 |
| F1 | 정밀도와 재현율의 조화평균 | 항목별 판단 성능 |
| 과적합 | 익숙한 사례에만 맞추어진 상태 | 새로운 공고에서도 개선되는지 |

이 대회는 24개 항목별 위반 클래스 F1을 단순 평균한 Macro F1을 사용한다. 정답과 예측은 ID로 맞춘 뒤 항목별로 비교한다. [평가 안내](https://dacon.io/competitions/official/236754/overview/evaluation)

## 4. 단계별 할 일

### A. 공고와 정답 이해

읽을 자료: [데이터 명세 요약](../02_data/02_detailed-spec.md), 배포 데이터의 README와 항목표.

- [ ] 공식 배포 데이터를 준비한다.
- [ ] `dev` 공고와 정답을 같은 ID로 연결한다.
- [ ] 공고문·첨부·메타데이터를 각각 확인한다.
- [ ] 정상 사례와 위반 사례를 함께 읽는다.
- [ ] 항목 하나의 적용 조건과 위반 이유를 자기 말로 적는다.

산출물: [판단 카드](03_workbook.md)의 첫 사례.

### B. 데이터 처리와 모델 없는 입출력 확인

읽을 자료: [Python 자습서](https://docs.python.org/ko/3/tutorial/)의 자료구조·입출력, [기본 베이스라인 해설](../03_baselines/02_gemma.md).

- [ ] 압축 JSONL에서 공고를 읽고 ID·문서 수·길이를 출력한다.
- [ ] 정답 CSV에서 항목별 위반 건수를 센다.
- [ ] 배포된 `baseline/script.py`의 인자와 환경변수 사용법을 읽는다.
- [ ] 제공 `--mock` 옵션으로 입출력 흐름을 확인한다.
- [ ] ID 누락·중복, 행 수, 49개 열, 0/1 값을 검증한다.

mock는 모델 없는 실행 흐름 확인이다. 실제 모델 판단, GPU 메모리, 속도, 성능을 검증한 것으로 기록하지 않는다. 명령 실행 위치와 환경변수는 배포본 README를 따른다.

### C. 실제 모델 실행과 첫 제출

읽을 자료: [평가 환경과 제출 안내](../01_competition/03_evaluation.md).

- [ ] 사용할 하드웨어와 모델 접근·다운로드 조건을 확인한다.
- [ ] 공식 베이스라인의 모델 설정과 의존성 버전을 확인한다.
- [ ] 작은 입력에서 실제 응답과 JSON 파싱을 확인한다.
- [ ] 긴 공고를 포함해 입력 길이·메모리·실행 시간을 확인한다.
- [ ] 원본 베이스라인과 설정을 보존한다.
- [ ] 실행·형식 검증을 통과한 코드를 제출하고 결과를 기록한다.

로컬 GPU가 없어도 데이터 읽기·mock·검증 코드는 진행할 수 있다. 실제 모델 실행 환경 확보는 별도 과제로 초반에 해결한다. 일반 노트북이나 Mac에서 평가 서버의 CUDA/vLLM 구성이 그대로 실행된다고 가정하지 않는다. 유료 GPU 이용이 필요하다면 사양·예상 시간·비용을 확인한 뒤 결정한다.

평가 서버는 개발용 대화형 API가 아니다. 제출 코드가 서버에서 실행되는 구조이며, 실제 추론 시간은 모델 초기화까지 포함해 확인해야 한다. [공식 평가 안내](https://dacon.io/competitions/official/236754/overview/evaluation)

### D. 기준 점수와 오답 분석

읽을 자료: [F1 문서](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html).

- [ ] 정답과 예측을 ID 기준으로 정렬·대조한다.
- [ ] 항목별 정밀도·재현율·F1과 전체 평균을 계산한다.
- [ ] 정상인데 위반이라고 한 사례와 위반을 놓친 사례를 구분한다.
- [ ] JSON 오류와 원문에 없는 근거 문구를 별도 집계한다.
- [ ] 틀린 공고의 실제 문장과 관련 조문을 읽는다.

오답 원인 후보: 문서 누락 / 적용 조건 오류 / 예외 누락 / 금액·날짜 비교 오류 / 출력 형식 오류 / 근거 추출 오류.

dev는 작으므로 점수 변동이 클 수 있다. 개선용 사례와 확인용 사례를 가능한 범위에서 구분하고 희소 항목의 표본 수를 함께 기록한다. 평가 사례의 정답을 프롬프트 예시로 넣은 뒤 같은 사례를 채점해 성능 개선으로 해석하지 않는다.

### E. 단순한 개선부터 비교

- [ ] 적용 조건·예외·출력 지시를 명확하게 정리한다.
- [ ] 관련 첨부가 실제 입력에 들어가는지 확인한다.
- [ ] 항목표에 연결된 관련 조문을 직접 제공해 본다.
- [ ] 같은 평가셋에서 변경 전후 점수·시간을 비교한다.
- [ ] 새로운 오답이 늘어난 항목도 확인한다.

법령 지식이 부족해 틀리는지 보려면 정답 판단에 필요한 조문을 사람이 골라 넣은 실험을 먼저 한다. 여기서 좋아진다면 검색을 붙일 근거가 된다.

### F. 필요하면 기본 RAG 추가

읽을 자료: [공식 RAG 베이스라인 해설](../03_baselines/03_rag.md).

- [ ] 제공 법령을 조문 단위로 나눈다.
- [ ] 검색한 조문 제목과 원문을 먼저 눈으로 확인한다.
- [ ] 관련 조문과 공고를 함께 모델에 제공한다.
- [ ] 조문 직접 제공 방식 및 RAG 없는 방식과 비교한다.
- [ ] 검색 실패와 모델 판단 실패를 구분한다.

법령은 판단 기준이고 제출 근거는 공고·첨부의 원문이다. 필요한 기재가 없는지 판단하는 항목은 검색 결과에 안 나왔다는 사실만으로 위반 처리하지 않는다. 문서 누락과 관측 범위를 함께 확인한다.

### G. 제출 후보 검증

- [ ] 모든 입력 ID가 정확히 한 번씩 포함된다.
- [ ] `id`, `v1~v24`, `e1~e24` 총 49열이다.
- [ ] 위반 값은 0/1이며 빈 값이 없다.
- [ ] 근거는 제공 공고·첨부 원문의 정확한 부분문자열이고 길이 조건을 충족한다.
- [ ] 비위반·부재탐지 항목의 근거 처리가 공식 규격과 맞는다.
- [ ] 환경변수 경로, `__main__` 가드, 출력 위치를 확인한다.
- [ ] 공고마다 고정 모델을 정상 호출한다.
- [ ] 추론 중 외부 API·다운로드 없이 동작한다.
- [ ] 설치·모델 로딩·추론을 포함한 실행 조건을 확인한다.
- [ ] 코드·설정·자료 버전과 제출 파일을 보존한다.

최종 세부 요건은 [평가 안내](https://dacon.io/competitions/official/236754/overview/evaluation)와 [규칙](https://dacon.io/competitions/official/236754/overview/rules)을 기준으로 확인한다.

## 5. 지금은 여기까지만, 필요할 때 확장

| 막힌 부분 | 먼저 해볼 것 | 이후 참고할 자료 |

| Python 데이터 처리 | 파일 한 건 읽기, 필터·집계 | Python for Data Analysis |
