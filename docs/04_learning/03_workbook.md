## 3. 오답 기록

| 공고 ID | 항목 | 정답 | 예측 | 원문 근거 | 오류 원인 | 개선 가설 | 재확인 결과 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

오류 원인은 문서 누락, 검색 실패, 적용 조건 오류, 예외 누락, 숫자 비교, 출력 파싱, 근거 추출 등으로 구분한다. 정답 자체가 의심되면 항목표·제공 조문과 함께 별도 검토하고 임의로 확정하지 않는다.

## 4. 실험 비교

| 실험 ID | 변경한 한 가지 | 평가 데이터 버전 | 평균 F1 | 약한 항목 F1 | 근거 검증 실패 수 | 실행 시간 | 채택 여부·이유 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

- 구성요소를 추가했다는 사실과 성능이 개선됐다는 사실을 구분한다.
- 전체 평균뿐 아니라 항목별 표본 수·성능도 보존한다.
- 프롬프트에 넣은 예시와 평가에 사용한 예시의 겹침을 기록한다.
- 좋아진 사례뿐 아니라 새로 틀린 사례도 읽는다.
