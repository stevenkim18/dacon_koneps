# 데이터 - 상세 명세

> 출처: https://dacon.io/competitions/official/236754/talkboard/417195?page=1&dtype=recent
> 게시일: 2026.08.26 14:25

본 대회 데이터의 상세 명세입니다. 데이터 탭의 요약 안내보다 자세한 내용을 담고 있습니다.

## 1. 배포 데이터 구조

    open.zip
    ├── README.md                      # 데이터 설명 요약
    ├── train_unlabeled.jsonl.gz       # 무라벨 입찰공고 20,000건
    ├── dev.jsonl.gz                   # 라벨 예시 공고 200건
    ├── dev_labels.csv                 # dev 200건 정답 라벨
    ├── sample_submission.csv          # 제출 양식 예시 10행
    ├── data/                          # 평가 서버 data/ 디렉토리의 로컬 사본
    │   ├── test.jsonl.gz              # 형식 확인용 샘플 10건
    │   ├── 항목표.json                # 24개 검토 항목 정의·근거 조문
    │   ├── 정답스키마_디코딩.json       # 제약 디코딩용 JSON 스키마
    │   └── 법령패키지/
    │       ├── 법령/                  # 법령·예규·행정규칙 23건 전문
    │       └── 중기부고시/             # 고시 제2025-96호 원본 + 세부품명 CSV
    └── baseline/
        ├── script.py                  # 베이스라인 추론 코드
        └── requirements.txt

평가 서버에서는 data/ 폴더가 제출물에 자동 마운트되며 읽기 전용입니다.

test.jsonl.gz만 실제 평가 데이터로 교체됩니다. 나머지 파일은 배포본과 동일합니다.

script.py가 data/의 ID를 그대로 읽어 output/submission.csv로 쓰도록 구성하면 로컬과 평가 서버에서 같은 코드로 동작합니다.

ID 접두사나 데이터 건수를 하드코딩하지 마세요.

## 2. 파일별 명세

### train_unlabeled.jsonl.gz

무라벨 입찰공고 20,000건입니다.

실제 나라장터 자체입찰 공고를 정규화·익명화한 것으로, 실제 위반 공고가 섞여 있을 수 있습니다.

정상 데이터라는 보장은 없습니다.

다음 용도로 활용할 수 있습니다.

- 자가 라벨링
- 학습·검증셋 구성
- 검색(RAG) 사례집
- 후처리 규칙 튜닝

### dev.jsonl.gz + dev_labels.csv

라벨 예시 세트입니다.

- 24개 검토 항목 전부에 위반 예시 포함
- 항목당 위반 예시 5~8건
- 정상 예시 112건
- 근거 문구 예시 포함
- dev_labels.csv는 제출 형식과 동일한 49열

프롬프트·후처리 개선 시 자가 채점 기준으로 사용할 수 있습니다.

실제 평가 데이터의 구성비는 dev와 다르며 공개하지 않습니다.

### data/항목표.json

24개 검토 항목 정의입니다.

- 기준일
- 표기규칙
- 부재탐지 항목(v10·v11·v16·v18·v20)
- 항목(v1~v24)

항목별 필드:

- 항목명
- 부재탐지 여부
- 국가계약법 근거 조문
- 지방계약법 근거 조문
- 비고

항목과 조문의 매핑은 판정 기준상 고정입니다.

24번 항목(v24)은 조문 위반이 아니라 공고서와 나라장터 등록값의 정보 불일치를 점검하는 항목입니다.

### data/정답스키마_디코딩.json

고정 LLM의 출력을 제출 형식 JSON으로 안정적으로 받기 위한 JSON 스키마입니다.

vLLM structured outputs에 사용할 수 있으며, 베이스라인 코드에 사용 예가 있습니다.

### data/법령패키지/

법령·예규·행정규칙 23건의 전문 TXT를 제공합니다.

중소벤처기업부 고시 제2025-96호의 원본 HWPX와 세부품명 CSV도 제공합니다.

품목 대조는 CSV를 사용합니다.

원문이 이미지인 구간이나 제외된 대형 별표는 각 TXT에 표기되어 있습니다.

채점은 이 스냅샷을 기준으로 하며, 대회 기간 중 법령 개정은 반영되지 않습니다.

평가 서버는 인터넷이 차단되므로 법령 검색(RAG)도 이 패키지로 구성해야 합니다.

### baseline/

script.py는 다음 전체 흐름을 포함합니다.

    데이터 로드 → 고정 모델 추론(제약 디코딩)
    → 근거 문구 검증 → submission.csv 저장

모델 없이 실행 흐름만 확인하려면 --mock 옵션을 사용할 수 있습니다.

해설 노트북과 법령 검색(RAG)을 붙인 변형은 코드 공유 게시판에 게시되어 있습니다.

## 3. 레코드 형식

JSONL 한 줄이 입찰공고 1건이며, 각 레코드는 아래 키로 구성됩니다.

| 키 | 내용 |
|---|---|
| id | 공고 식별자. 제출 파일의 id 열에 그대로 사용 |
| docs | 문서 배열 |
| meta | 나라장터 등록 정보 21필드 |
| dropped_doc_counts | 길이 예산 초과로 제외된 문서의 종류·개수 |
| input_completeness | 관측 완전성 bool 4종 |
| anon_applied | 익명화 적용 여부. 전건 true |
| assembly_policy_version | 데이터 조립 규약 버전 |

docs의 각 원소는 doc_id, type, text를 가집니다.

type은 공고문·규격서·과업지시서·제안요청서·예외공표서 5종입니다.

text는 NFC 정규화 텍스트이며 표는 | 구분자로 행과 열을 복원합니다.

공고문은 항상 1건 이상 포함됩니다.

위반이 첨부 문서에만 나타나는 항목이 있으므로 공고문만 읽고 판정을 끝내지 않는 것을 권장합니다.

dropped_doc_counts가 비어 있지 않은 공고는 일부 첨부가 제외된 상태입니다.

첨부에 없으니 위반이라고 단정하면 부재탐지형 항목 판정이 틀릴 수 있습니다.

## 4. meta 21필드와 익명화

meta 필드는 다음과 같습니다.

- 적용계약법
- 업무구분
- 계약방법
- 낙찰방법
- 낙찰하한율
- 배정예산금액
- 입찰추정가격
- 소관구분
- 공동도급구성방식
- 정보화사업여부
- 세부품명번호목록
- 제한지역코드목록
- 지역제한여부
- 면허업종제한목록
- 업종제한여부
- 조항호내용
- 공고게시일자
- 개찰예정일자
- 긴급공고여부
- 입찰방법
- 조달방식

값이 없으면 null, 등록 자체가 안 됐으면 미입력입니다.

meta는 원칙적으로 본문과 정합하지만 24번 항목만 예외입니다.

기관명·담당자·연락처·주소·공고번호는 토큰으로 치환되어 있습니다.

    [수요기관(기초자치단체)|지역=r1]

괄호 안 기관 유형은 판정에 사용할 수 있습니다.

    [지역:r1|단위=기초|광역=경기도]

한 문서 안에서 r1과 r2는 서로 다른 지역이며, 광역 시도명은 원문 그대로 유지됩니다.

금액·수량·날짜·법령 조문·품명·규격은 치환되지 않았습니다.

## 6. 제출 형식

49열:

- id
- v1~v24
- e1~e24

행 수는 입력 건수와 동일해야 합니다.

위반 여부는 정수 0/1로 기재합니다.

판단이 어려운 항목도 비우지 말고 0으로 제출합니다.

근거 문구는 제공된 본문의 부분문자열 그대로 사용하며, 500자 이하입니다.

위반이 아니거나 부재탐지형 항목이면 빈칸입니다.

인코딩·형식:

- UTF-8, BOM 없음
- NFC 정규화
- RFC4180 quoting
- 수식 접두 문자 =, +, @ 금지

리더보드는 v1~v24만 반영하며, e1~e24는 2차 정성평가 재료로 사용됩니다.

## 7. 자가 라벨링

본 대회는 라벨이 부착된 학습 데이터를 제공하지 않습니다.

무라벨 데이터에 스스로 라벨을 만들어 쓰는 것이 전면 허용됩니다.

라벨 생성 방법에는 제한이 없습니다.

- 수작업
- 규칙 기반
- 모델 기반

라벨 생성 단계에서는 외부 LLM(상용 API 포함)도 사용할 수 있습니다.

단, 외부 LLM에는 대회 제공 자료만 입력할 수 있으며, 웹 검색·외부 문서 결합으로 원문을 조회하거나 외부 데이터를 가져오는 것은 금지됩니다.

생성한 라벨은 로컬 검증셋, RAG 사례집, 후처리 규칙 튜닝 재료로 활용할 수 있습니다.

생성한 라벨을 공유하려면 코드 공유 게시판을 통한 전체 공개만 가능합니다.

## 8. 시작 가이드

1. baseline/script.py --mock로 모델 없이 입출력 흐름 확인
2. dev 200건으로 프롬프트·후처리 개선
3. dev_labels로 자가 채점
4. 무라벨 20,000건에 자가 라벨링을 적용하여 검증셋·사례집 확장
5. submit.zip 구성 후 제출

## 9. 자주 묻는 질문

- 학습 데이터 라벨은 제공되지 않으며 자가 라벨링이 과제의 일부입니다.
- dev 200건은 학습·검증에 사용할 수 있습니다.
- 외부 데이터와 나라장터 API는 사용할 수 없습니다.
- 파이프라인에 결합하는 법령은 배포된 법령 패키지를 사용해야 합니다.
- 파인튜닝과 LoRA 어댑터는 불허입니다.
- 모델 가중치는 제출하지 않습니다.
- 정규식·규칙 기반 후처리는 가능하지만 공고마다 고정 모델 정상 호출이 필요합니다.
- 로컬 GPU가 없어도 --mock와 dev 데이터로 파이프라인을 개발할 수 있습니다.
- 근거 문구는 리더보드 점수에는 반영되지 않지만 2차 평가에서 정성평가됩니다.
- 제출 결과가 바로 나오지 않는 것은 채점 대기일 수 있습니다.
- if __name__ == "__main__": 가드와 PPS_* 환경변수 사용이 필요합니다.
- 평가 서버는 인터넷이 차단되어 모델 ID 다운로드가 불가능합니다.
- LLM과 임베딩 모델을 함께 사용할 수 있지만 GPU 동시 로드는 보장되지 않습니다.
