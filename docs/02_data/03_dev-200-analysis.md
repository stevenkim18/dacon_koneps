# dev 200건 분석

> 분석일: 2026-09-16 KST  
> 대상: `open/dev.jsonl`, `open/dev_labels.csv`  
> 재현 명령: `python scripts/analyze_dev.py`

## 1. 결론

dev 200건은 **모델 성능을 대표하는 일반 표본이라기보다, 24개 위반 항목을 빠짐없이 보여 주기 위해 구성한 예시·검증 세트**에 가깝다. 정상 공고는 112건, 하나 이상의 위반이 있는 공고는 88건이며, 24개 항목 각각의 양성은 5~8건뿐이다. 따라서 dev 점수 하나만 보고 일반화 성능을 확신하면 안 된다.

현재 공식 베이스라인의 `build_context(max_chars=4000)`은 더 직접적인 병목이 있다.

- 200건 모두 첫 번째 공고문만 입력된다.
- 규격서 63건, 과업지시서 53건, 제안요청서 57건은 한 건도 입력되지 않는다.
- 전체 문서 3,516,026자 중 790,219자, 즉 22.5%만 남는다.
- 제공 정답 근거 54개 중 47개만 남고 7개는 사라진다.
- 특히 첨부에 근거가 있는 `v9`의 확인 가능한 근거 3개가 모두 사라진다.

그러므로 다음 개선의 우선순위는 복잡한 RAG보다 먼저 **공고문과 첨부를 항목별로 골고루 모델에 전달하는 입력 구성**이다.

## 2. 분석 범위와 해석 기준

이번 분석은 모델 추론 없이 다음을 확인했다.

1. JSONL과 CSV의 ID·행·열 구조
2. 정상/위반 공고 수와 항목별 양성 수
3. 한 공고에 여러 위반이 함께 있는 정도
4. 문서 종류·길이·첨부 탈락 상태
5. 제공 근거 문구가 원문에 정확히 존재하는지
6. 공식 베이스라인의 4,000자 문서 입력에 근거가 남는지
7. 주요 메타데이터의 분포와 눈에 띄는 이상값

여기서 “양성”은 특정 `v` 열의 값이 1이라는 뜻이다. 예를 들어 한 공고에 `v3=1`, `v8=1`이면 위반 공고 1건이지만 양성 라벨 셀은 2개다.

실제 모델의 토크나이저가 수행하는 `fit_to_budget`은 실행하지 않았다. 따라서 4,000자 분석은 **토큰 예산 적용 전 상한**이며, 실제 입력은 더 줄어들 수 있다.

### 4.3 함께 나타나는 위반

이 조합은 조건이 논리적으로 연결된 항목이 많다는 신호다. 예를 들어 실적제한을 감지한 뒤 금액, 기관 특정 여부, 지역제한을 함께 확인하는 식으로 항목별 판단을 연결할 수 있다. 다만 dev에서 몇 번 같이 나왔다는 이유만으로 한 항목을 예측했을 때 다른 항목도 자동으로 1로 만드는 것은 과적합 위험이 크다.

## 10. 눈에 띄는 값과 주의점

다음은 자동 검사에서 발견한 값이다. 정답 오류라고 확정한 것이 아니라, 숫자·날짜 규칙을 만들 때 방어 처리가 필요한 사례다.

- `PPS-DEV-050`: 개찰예정일이 공고게시일보다 1일 빠름
- `PPS-DEV-088`: 개찰예정일이 공고게시일보다 30일 빠름
- `PPS-DEV-094`, `PPS-DEV-142`: 배정예산금액과 입찰추정가격이 모두 1원

날짜 차이나 금액 임계값만으로 바로 위반을 만들기보다, 비정상값·미입력·문서 불일치를 별도 상태로 처리해야 한다. 특히 `v24`는 메타와 공고서의 대조 결과가 필요하므로 메타 값 하나만 보고 판단할 수 없다.

## 11. 구현 우선순위

### 1순위: 첨부가 실제로 들어가는 컨텍스트 구성

공고문 4,000자 선두만 쓰지 말고 다음 중 단순한 방식부터 비교한다.

1. 공고문·규격서·과업지시서·제안요청서에 최소 글자 예산을 각각 배분
2. 문서별 앞부분과 뒷부분을 함께 보존
3. 항목별 키워드 주변 문단을 추출하고 정확한 원문 위치를 유지
4. `v9`, `v22`처럼 첨부 의존성이 높은 항목은 별도 호출 또는 별도 컨텍스트 사용

### 2순위: 24개 항목을 조건 묶음으로 나누기

- 실적·지역 제한: v1~v8
- 물품·중소기업 제한: v10~v19
- SW·공동도급·현장설명회: v20~v23
- 공고문과 메타 대조: v24

한 번의 짧은 입력으로 24개를 모두 판정하기보다, 관련 메타와 문서를 묶어 보내면 판단 조건과 근거가 덜 희석된다. 단, 평가 서버에서는 공고마다 고정 LLM을 최소 1회 정상 호출해야 하고 전체 실행시간은 2시간이므로 호출 수와 배치를 함께 측정해야 한다.

### 3순위: 근거 추출과 위반 판단을 분리

먼저 후보 문장을 원문의 정확한 부분문자열로 찾고, 그 후보와 관련 메타·법령을 모델에 전달한다. 모델이 만든 요약문을 근거로 저장하지 말고, 선택된 원문 span을 `e` 열에 복사해야 한다.

### 4순위: dev 과적합 방지

- 순서 기반 분할 금지
- 항목별 5~8개라는 실제 표본 수와 함께 점수 기록
- 전체 Macro F1뿐 아니라 항목별 TP/FP/FN 확인
- 같은 dev 정답을 프롬프트 예시로 넣고 같은 행을 평가한 결과는 성능 개선으로 간주하지 않기
- 최종 규칙은 제공된 법령 패키지와 항목표의 조건으로 설명 가능하게 유지
