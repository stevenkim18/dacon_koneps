## 베이스라인 구성

### 입력 데이터

레코드 1건은 id, docs, meta, dropped_doc_counts로 구성됩니다.

- 공고문은 반드시 1개 이상 포함
- 규격서·과업지시서·제안요청서는 공고마다 다름
- 길이 예산으로 제외된 첨부는 dropped_doc_counts에 종류·개수 기록
- 한글 텍스트는 NFC로 정규화

### 항목표와 출력 스키마

- data/항목표.json
  - 24개 항목 이름
  - 부재탐지 여부
  - 비고
- data/정답스키마_디코딩.json
  - structured output 제약 디코딩용 JSON 스키마

부재탐지형 항목은 v10, v11, v16, v18, v20입니다.

부재탐지형은 있어야 할 문구가 없는 것이 위반이므로 인용할 원문이 없습니다. 스키마에서 근거 문구를 null로 고정합니다.

### 프롬프트 구성

- system
  - 출력 형식 지시
  - 24개 항목 목록
- user
  - 나라장터 meta
  - 문서 내용
  - 공고문 먼저
  - 첨부문서 원래 순서 유지

문서가 글자 수 상한을 넘으면 뒤쪽 첨부부터 제외하고 [미수록 문서]로 표시합니다.

### 모델 출력 후처리

모델 출력 JSON을 24개 항목 딕셔너리로 변환합니다.

빠진 항목은 제출 스키마 유지를 위해 0으로 보완합니다.

후처리에서는 다음을 확인합니다.

- 부재탐지형 항목의 근거 문구 비우기
- 비위반 항목의 근거 문구 비우기
- 근거 문구가 원문에 포함되는지 확인
- 근거 문구 500자 제한
- 수식 접두 문자 방지
- v 값이 0/1인지 확인

### 제출 CSV 검증

저장 후 다음 항목을 확인합니다.

- 49개 컬럼
- 입력과 동일한 행 수
- ID 유일성
- v 값 0/1
- e 값 500자 이하
- 부재탐지형 e 빈칸
- UTF-8, BOM 없음
- RFC4180 quoting
- NFC 정규화

### 실행 구조

vLLM은 하위 프로세스를 spawn 방식으로 생성할 수 있으므로 모델 생성 및 실행 코드는 다음 가드 아래에 두어야 합니다.

    if __name__ == "__main__":
        ...

모델 경로는 다음 환경변수에서 읽습니다.

- PPS_MODEL_DIR
- PPS_EMBED_DIR
- PPS_DATA_DIR
- PPS_OUTPUT_DIR

모델 없이 전체 입출력 흐름을 확인하려면 mock 옵션을 사용할 수 있습니다.

## 제출용 핵심 체크

- 공고마다 고정 LLM을 최소 1회 정상 호출
- 공고문과 첨부문서 모두 context에 포함
- 다른 공고의 결과를 재사용하지 않음
- 외부 API·인터넷 호출 없음
- 모델 가중치 제출 없음
- RAG 인덱스 등 정적 자산만 model/에 포함
- output/submission.csv 생성
