## 기본 구조

Gemma 제약 디코딩 베이스라인의 전체 흐름을 유지하면서, 제공된 법령 패키지를 검색하여 관련 조문을 프롬프트에 추가합니다.

- 공고 데이터 로드
- 문서 context 구성
- 법령 조문 검색
- 고정 Gemma 호출
- structured JSON 출력
- 결과 파싱·후처리
- 근거 문구 검증
- submission.csv 저장

## 법령 RAG 구성

### 법령 문서 로드

data/법령패키지/법령/*.txt에 있는 법령·예규·행정규칙 전문을 읽습니다.

### 조문 분할

법령 텍스트를 조문 제목 단위로 분할합니다.

제 n조 형식을 기준으로 관련 조문을 나눕니다.

### 검색 인덱스

한국어 토큰과 2-gram을 사용하여 BM25 인덱스를 구성합니다.

정적 RAG 인덱스는 제출물에 포함할 수 있습니다.

### 검색 쿼리

공고문의 앞부분을 최대 약 3,000자까지 검색 쿼리로 사용합니다.

관련성이 높은 조문을 최대 8개 정도 검색하며, 검색 결과는 약 8,000자 이내로 제한합니다.

### 프롬프트 반영

검색한 조문은 다음과 같은 보조 context로 추가합니다.

    [검색된 법령 조문]

법령 검색 결과는 판정 보조용입니다.

최종 근거 문구는 법령 조문이 아니라 제공된 공고문·첨부문서에서 추출해야 합니다.

## 고정 모델 및 제출 제약

- 고정 LLM: google/gemma-4-26B-A4B-it
- 보조 임베딩 모델: BAAI/bge-m3
- 모델 가중치·LoRA·QLoRA 제출 금지
- 공고마다 고정 LLM 정상 호출 필요
- 외부 데이터·외부 API·인터넷 사용 금지
- 다른 공고의 결과·예측·통계 재사용 금지
- model/에는 정적 RAG 인덱스만 포함 가능

## 출력 후처리

Gemma 베이스라인과 동일하게 처리합니다.

- 구조화 JSON 파싱
- 빠진 항목은 0으로 보완
- 비위반 근거 문구 공란
- 부재탐지형 근거 문구 공란
- 제공 문서 원문에 존재하는 부분문자열인지 확인
- 근거 문구 최대 500자
- v1~v24는 0/1
- output/submission.csv에 49열 저장

RAG에 사용한 법령 문구는 e1~e24의 근거 문구로 직접 제출할 수 없습니다.

근거 문구는 반드시 해당 공고의 docs[].text에서 찾아야 합니다.
