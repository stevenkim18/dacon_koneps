## 1. 대회 개요

- 대회명: 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회
- 주제: 나라장터 입찰공고의 법령 위반 여부 자동 판정
- 입력: 입찰공고문·첨부문서·나라장터 메타데이터
- 출력:
  - `v1~v24`: 24개 위반 항목의 위반 여부 `0/1`
  - `e1~e24`: 위반을 판단한 근거 문구
- 기간: 2026.08.26 10:00 ~ 2026.09.30 10:00
- 상금: 총 4,200만 원
- 참가 자격: 대한민국 국민 누구나
- 주최: 행정안전부, 한국지능정보사회진흥원
- 주관: 조달청
- 운영: DACON

핵심 제약은 모든 참가자가 동일한 고정 모델을 사용하는 코드 제출형 대회라는 점입니다.

- 고정 LLM: `google/gemma-4-26B-A4B-it`
- 임베딩 모델: `BAAI/bge-m3`
- 파인튜닝, LoRA/QLoRA, 모델 가중치 제출 금지
- 제출 코드에서는 공고별로 고정 LLM을 최소 1회 정상 호출해야 함
- 외부 데이터/API/웹 크롤링은 금지

## 2. 페이지별 핵심 내용

### [개요](https://dacon.io/competitions/official/236754/overview/description)

나라장터 공고는 공고문, 첨부문서, 메타데이터에 정보가 나뉘어 있어 사람이 모든 법령 위반 여부를 검토하기 어렵습니다.

참가자는 한 공고를 대상으로 다음을 판단해야 합니다.

1. 공고문과 첨부문서의 내용 확인
2. 나라장터 메타데이터 확인
3. 24개 법령·규칙 위반 항목별 위반 여부 판정
4. 위반 시 원문에서 근거 문구 추출

24개 항목 중 23개는 국가계약법, 지방계약법, 중소기업자간 경쟁제품 관련 규정, 소프트웨어진흥법 등에 기반하며, `v24`는 공고서와 나라장터 메타데이터의 불일치를 판정합니다.

라벨이 제공된 학습 데이터는 없으며, 참가자가 20,000건의 비라벨 데이터에서 직접 라벨을 생성할 수 있습니다.

### [평가](https://dacon.io/competitions/official/236754/overview/evaluation)

#### 평가 지표

- 24개 항목 각각에 대해 위반 클래스 `1`의 F1-score 계산
- 24개 F1-score의 단순 평균
- 모든 항목이 평가 대상
- `v1~v24`만 리더보드 점수에 사용
- `e1~e24`는 2차 정성평가에 사용

#### 평가 절차

- 1차: Private Score 기준 상위 15팀 선정
- 2차:
  - 제출 코드 재현성 검증
  - 위반 근거 문구의 정성평가
  - 규칙 준수 여부 확인
- 최종 수상팀: 7팀
- 최종 점수: 정량평가 80% + 정성평가 20%

근거 문구는 반드시 제공된 공고문·첨부문서의 **정확한 부분 문자열**이어야 합니다. 요약문, 수정 문장, 생성 문장은 인정되지 않습니다.

다음 부재 탐지 항목은 정성평가 근거 대상에서 제외됩니다.

- `v10`
- `v11`
- `v16`
- `v18`
- `v20`

#### 제출 파일

```text
submit.zip
├── script.py          # 필수
├── requirements.txt   # 선택
└── model/             # 선택, 정적 RAG 자료 등
```

- 결과 파일: `output/submission.csv`
- 컬럼 수: 총 49개
  - `id`
  - `v1~v24`
  - `e1~e24`
- `v` 값은 반드시 정수 `0` 또는 `1`
- `e` 값은 최대 500자
- ID 중복·누락 금지
- UTF-8, BOM 없음
- 압축 파일 최대 2GB
- 실행 시간 최대 2시간
- 일일 제출 횟수 1회
- 실행 중 인터넷 사용 불가

서버 환경 변수는 다음을 사용해야 합니다.

```text
PPS_DATA_DIR
PPS_OUTPUT_DIR
PPS_MODEL_DIR
PPS_EMBED_DIR
```

경로를 하드코딩하면 서버 실행에 실패할 수 있습니다.

### 데이터셋

- `train_unlabeled.jsonl.gz`
  - 20,000건
  - 위반 여부 라벨 없음
  - 자기 라벨링, RAG 사례집, 검증셋 구성에 활용 가능
- `dev.jsonl.gz`
  - 200건
  - 모든 위반 항목에 양성 사례 포함
  - 실제 평가셋과 분포가 다를 수 있음
- `dev_labels.csv`
  - 제출 파일과 같은 49컬럼 구조
- `test.jsonl.gz`
  - 로컬에는 형식 확인용 10건
  - 실제 서버에서는 1,853건 평가 데이터로 교체

각 레코드는 대략 다음 구조입니다.

```text
id
docs[]
  - doc_id
  - type
  - text
meta                 # 21개 필드
dropped_doc_counts
input_completeness
anon_applied
assembly_policy_version
```

`docs`에는 공고문뿐 아니라 규격서, 과업지시서, 제안요청서 등이 포함될 수 있습니다. 위반 근거가 첨부문서에만 있을 수 있으므로 공고문만 보고 판단하면 안 됩니다.

첨부문서가 길이 제한으로 제외된 경우 `dropped_doc_counts`가 기록됩니다. 이때 문서가 없다는 이유만으로 “부재 위반”이라고 판단하면 안 됩니다.

평가셋에도 `meta` 21개 필드가 동일하게 포함되므로 본문에서 직접 추출할 필요가 없습니다.

## 4. [코드 공유](https://dacon.io/competitions/official/236754/codeshare)

고정 게시된 주요 베이스라인은 다음 두 가지입니다.

- [Baseline: Gemma 제약 디코딩 법령위반 판정](https://dacon.io/competitions/official/236754/codeshare/14154?page=1&dtype=recent)
  - 고정 Gemma 호출
  - JSON 구조화 출력
  - 24개 항목 판정
  - 근거 문구 원문 검증
  - 제출 CSV 검증
- [Baseline: Gemma + 법령 RAG 법령위반 판정](https://dacon.io/competitions/official/236754/codeshare/14155?page=1&dtype=recent)
  - 위 베이스라인에 법령 RAG 추가
  - 제공된 법령 패키지를 조문 단위로 분할
  - BM25로 관련 법령 조문 검색
  - 검색한 법령은 판단 보조용으로만 사용
  - 최종 근거 문구는 반드시 공고문·첨부문서에서 추출

추천 구현 흐름:

```text
데이터 로드
→ 공고문과 첨부문서 정리
→ meta + 문서 context 구성
→ 법령 RAG 검색
→ 고정 Gemma 호출
→ JSON 파싱
→ v 값 정규화
→ e 값 원문 부분문자열 검증
→ submission.csv 생성
```

## 6. 리더보드·팀·제출 메뉴

### [리더보드](https://dacon.io/competitions/official/236754/leaderboard)

- `Public` 탭과 `Ranking Chart` 탭 제공
- 순위, 팀명, 팀원, 점수, 제출 횟수, 등록일 표시
- 2026-09-15 확인 당시 공개 상위 점수는 약 0.7652
- 공개 리더보드는 최종 순위가 아님
- Private Score와 2차 재현성·정성평가가 최종 결과에 반영됨

### 팀·제출

상단에는 `팀`, `제출` 탭이 있으나 현재 비로그인 브라우저에서는 개인별 팀 정보와 제출 이력 상세 화면이 노출되지 않았습니다.

공개된 규칙 기준으로 기억해야 할 내용은 다음과 같습니다.

- 팀 최대 5명
- 일일 제출 1회
- 제출 파일은 `submit.zip`
- 결과 파일은 `output/submission.csv`
- 제출 마감 전 충분한 실행 시간을 확보해야 함
