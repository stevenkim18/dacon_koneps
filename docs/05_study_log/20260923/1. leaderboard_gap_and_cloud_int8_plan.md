## 3. 가설 — 4bit로 LLM 쪽 아이디어를 잘못 기각해 왔다

- 09-17 이후 LLM 판정을 넓히는 시도(전용 호출, 품목 호출, thinking, 문맥 확대, v1 필드)는 **전부 로컬 MLX 4bit**로 재서 기각했다. 코드 주석에도 "4bit 모델이 못 한다"(`needs_goods_item_call`)가 있다.
- 서버는 vLLM **int8**이다. LLM 의존을 늘릴수록 dev−Public 격차가 커졌다(−0.096 → −0.159, `20260918/1. sme_level_public_score.md`). 로컬이 서버 동작을 대표하지 못한다는 신호일 수 있다.
- **검증되지 않았다.** 격차가 dev 과적합에서 올 수도 있다. 그래서 먼저 잰다.

해석: 서버 실행이 망가지는 문제(JSON 실패·잘림)는 없다. 대신 **LLM 출력 분포가 4bit와 달라** 4bit에 맞춰 조정한 판정 규칙이 int8에서 어긋난다. 특히 v9 모델명 판별 호출. Public은 int8 출력으로 채점되므로 **int8 원본 출력(`raw/`)으로 규칙을 다시 맞추는 것**이 GPU 없이 할 수 있는 다음 레버다. dev 과적합 여부는 무라벨 750 int8 출력으로 따로 확인해야 한다.

**정정(같은 날).** int8은 dev를 0.024만 바꿨다(0.8706 → 0.8468). int8로 재도 dev−Public 격차 약 0.16이 남으므로 3절 가설("4bit가 격차의 주원인")은 **일부만 맞다**. 격차의 대부분은 dev에 맞춘 규칙이 평가 공고에서 일반화되지 않는 쪽으로 본다(추정).
v9 int8 오탐 10건 중 8건은 모델명 호출이 새로 true라고 한 경우인데, 정답 줄("GB10 Grace Blackwell Superchip", "파종기(DPM-8000GMP)")과 오답 줄("RTX Pro 4000 Blackwell", "형식명 : D851")이 형태로 구별되지 않는다. 호출을 빼면 int8 v9 0.476 → 0.400이라 유지한다. 규칙으로 고칠 방법은 없다.
