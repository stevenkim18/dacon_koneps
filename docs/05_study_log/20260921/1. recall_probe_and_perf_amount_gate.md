## 3. `rx_performance`는 **같은 줄에 금액이 있어야만** 실적 제한으로 인정한다

```python
if not (re.search(r"이상|보유|있는", s) and parse_amounts(s)):   # ← parse_amounts가 필수
    continue
```

그런데 항목표를 보면 금액이 필요한 것은 **v3(실적제한 1배수 이상)뿐이다.**

- v2 고시금액 미만 실적제한 — 실적 제한이 있는지만 본다
- v4 고시금액 이상 특정기관·특정실적 — 발주처 한정만 본다
- v8 중복제한(실적+지역) — 두 제한의 존재만 본다

즉 **금액 없이 기간·건수로 구체화한 실적 요구는 v2·v4·v8에서 구조적으로 보이지 않는다.**
자격 섹션 안에 실적 문장이 있는데 `실적제한=False`인 공고가 무라벨 750건 중 **148건**이었고,
앞 10건을 라벨하니 3건이 진짜 누락이었다.

**법정 일반자격 상투문**(지방계약법 시행령 제13조 `당해 용역을 수행할 수 있는 신용과 실적이 있는 자` — dev DEV-165 v2=0),

### 판단

**dev는 -0.0086이지만 채택 쪽이다.** 이유는 셋이다.

1. **dev에는 v2·v4 누락이 0건**이다(v2 7/0/0, v4 5/0/1의 1은 다른 원인). 이득을 측정할 수 있는 구조가 아니고, 오탐만 잡힌다. 금액 요건이 dev에서 완벽했던 것은 **dev의 실적 문장이 전부 금액을 달고 있었기 때문**이다.
2. **F1/2 정리**: 새 탐지의 정밀도가 `현재 F1/2 = 0.336`을 넘으면 F1은 오른다. 손라벨 0.75~0.90은 두 배 넘게 넘는다.
3. v2 예측 양성이 12건 → 44건(환산)으로 **3.7배**가 된다. 평가셋에 v2 양성이 있다고 대회가 명시했으므로 지금은 재현율이 구조적으로 낮다.

**dev에 더 맞추는 튜닝은 하지 않았다.** 남은 dev 오탐 3건은 2개 공고(`실적의 합`, `※ 연구용역의 범위`)에서 나온 것이고, 여기에 예외를 더 붙이는 것이 09-19~20에 전달률을 음수로 만든 바로 그 행동이다.
