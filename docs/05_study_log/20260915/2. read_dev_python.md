# Python으로 공고 읽기

## 실습 내용

- [read_dev.py](../../../scripts/read_dev.py)로 `open/dev.jsonl.gz`에서 `PPS-DEV-01`을 찾아 출력한다.
- `.gz`는 압축 파일이며, JSONL은 한 줄에 JSON 데이터 한 건이 들어 있는 형식이다.

## 실행 방법

프로젝트 루트 폴더의 터미널에서 실행한다. 추가 패키지 설치는 필요 없다.

```bash
python3 scripts/read_dev.py
```

## 확인된 결과

스크립트 실행 시 아래 정보와 공고문 전체가 출력되는 것을 확인했다.

```text
공고 ID: PPS-DEV-01
문서 수: 2
문서 종류: 공고문, 과업지시서
```

## 코드에서 읽을 부분

1. `gzip.open(...)`: 압축 파일을 텍스트로 연다.
2. `json.loads(line)`: 한 줄의 JSON을 Python 딕셔너리로 바꾼다.
3. `notice["id"]`: 원하는 공고 ID인지 확인한다.
4. `notice["docs"]`: 문서 목록을 가져와 종류와 공고문 본문을 출력한다.

## 추가 실습: 공고와 정답 연결하기

- `open/dev_labels.csv`에서 같은 ID의 정답 행을 찾는다. 행 순서가 아닌 ID로 연결한다.
- `open/data/항목표.json`에서 `v1~v24`의 항목명을 가져온다.
- 24개 항목의 **이름·제공 정답·근거**를 출력하고 위반·비위반 개수를 센다.
- 근거 문장이 있으면 공고문과 첨부문서 중 어느 하나에 원문 그대로 포함되는지 확인한다.

### 확인된 결과

```text
v1 | 참가자격 특정기관 제한 | 위반
근거: 라. 본 용역은 … 산학협력단만 참여 가능함
근거 문장이 공고문·첨부문서에 있는가: True

v2 | 고시금액 미만 실적제한 | 비위반
근거: 없음
...
요약: 제공 정답 기준 위반 1개 / 비위반 23개
```

위 예시의 근거는 생략 표기이며, 실제 실행에서는 전체 문장이 출력된다. AI의 예측이 아니라 배포된 정답을 읽은 결과다.

### 코드에서 읽을 부분

1. `csv.DictReader(...)`: CSV의 헤더를 키로 사용해 각 행을 읽는다. 값은 문자열이다.
2. `json.load(...)`: 항목표 JSON 파일 전체를 읽는다.
3. `range(1, 25)`: 1부터 24까지 반복하며 `v번호`, `e번호`를 만든다.
4. `int(...)`: 정답 문자열을 정수로 바꾸어 위반 개수를 센다.
5. `any(evidence in doc["text"] ...)`: 근거가 포함된 문서가 하나라도 있는지 확인한다. 빈 근거는 검사하지 않는다.

배운 점: 공고 한 건에는 24개 항목별 정답이 붙으며, 각 항목의 위반 여부(`v`)와 근거(`e`)를 함께 읽는다.
