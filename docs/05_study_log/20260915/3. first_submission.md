## 피드백과 다음 실습

첫 제출·채점 목표는 달성했다. 다음은 점수가 낮은 원인을 확인할 차례다.

1. **AI가 실제로 읽는 입력부터 확인한다.** 베이스라인의 `build_context`는 기본 4,000자 예산으로 문서를 구성한다. 긴 첫 공고문은 잘리고, 뒤의 첨부는 빠질 수 있다.
2. `PPS-DEV-01`의 전체 문서와 `build_context` 결과를 비교해 잘린 부분·빠진 첨부·정답 근거의 포함 여부를 확인한다. 모델 설치 없이 가능하다.
3. 이후 실제 dev 예측을 확보하면 항목별 F1과 오답을 분석한다. 현재 로컬의 mock CSV는 실제 예측 평가에 사용하지 않는다.
4. 입력 길이 또는 프롬프트 등 한 가지씩 변경하고 점수·시간을 기준 버전과 비교한다.

입력 누락은 코드에서 확인한 개선 후보이며, 이번 점수의 원인으로 확정한 것은 아니다. 길이를 늘리면 실행 시간과 메모리 사용량도 확인해야 한다.
