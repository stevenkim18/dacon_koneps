# v10 품목 융합 규칙 — 변형 4종을 재채점하고 전부 기각

기준: `submissions/20260919_sme_recall_reviewed/script.py` (Public 0.6716800657).
**새 추론은 하지 않았다.** 저장된 MLX 출력(`runs/mlx/extract_outputs.jsonl`·`item_outputs.jsonl`·`model_outputs.jsonl`)으로 후처리만 다시 돌렸다.

## 1. 결론

- 전용 품목 호출의 답을 더 믿는 방향(B·D·E)은 **확실히 손해다.** v10 오탐이 3건 → 15~18건으로 터진다.
- `uninformed` 예외를 없애는 변형(C)만 dev에서 이득이지만 **무라벨 250 정밀도가 0.765 → 0.750으로 떨어져** 채택 규칙에 걸린다.
- **v10의 누락 4건은 후처리 규칙으로 되살릴 수 없다.** 남은 길은 품목 식별 프롬프트를 고쳐 재추론하는 것뿐이다.

## 3. 변형 4종

`decide()`의 품목 융합 블록만 바꿨다. 현행은 다음과 같다.

```python
uninformed = bool(re.search(r"명시되지|없어|없음|불가|알 수 없|확인할 수 없|포함되어 있지",
                            str(item.get("계약목적물_요약") or "")))
veto = item["세부품명번호"] == "해당없음" and not uninformed
code = "해당없음" if veto else (base or "해당없음")
```

| 변형 | 바꾼 것 |
|---|---|
| **B** `or` | 거부권은 유지하되, 본 호출이 경쟁제품을 못 고르면 전용 호출의 코드를 쓴다 |
| **C** `strictveto` | `uninformed` 예외를 없앤다. 전용 호출의 "해당없음"을 항상 존중 |
| **D** | B + C |
| **E** `noveto` | 거부권 자체를 없애고 본 호출 우선, 못 고르면 전용 호출 |

**B·D·E 기각.** 누락 4건 중 2건을 되살리는 대가로 오탐이 3 → 15~18건이 된다.
전용 호출은 본 호출이 "해당없음"이라고 한 공고에서 과하게 코드를 부여한다.
이것으로 "전용 호출을 더 믿는" 방향은 측정으로 닫혔다.

## 5. C를 기각한 이유

C는 dev에서 이득이다. DEV-165의 v10·v13 오탐 2건이 사라져 교차검증이 0.8075 → **0.8107**(+0.0032)로 오른다.

그러나 품목을 "해당없음"으로 더 자주 밀어내면 `comp=False`가 되고, **v12(직접생산확인 요구 ∧ 비경쟁제품)가 대신 켜진다.**

| 지표 | 현행 | C |
|---|---:|---:|
| 교차검증 | 0.8075 | **0.8107** |
| 무라벨 250 정밀도 | **0.765** (정탐 39 / 오탐 12) | 0.750 (정탐 39 / **오탐 13**) |

실제 LLM 출력이 있는 950건 전체를 대조하면 현행과 갈리는 공고는 2건이다.

- `PPS-DEV-165` v10 1 → 0, v13 1 → 0 (둘 다 라벨 0이므로 개선)
- `PPS-D-021217` v12 0 → 1 (자가 라벨 기준 오탐)

채택 규칙은 **교차검증 유지 AND 무라벨 정밀도 상승**이다. 정밀도가 떨어졌으므로 채택하지 않는다.
덧붙여 이 이득은 dev 오답을 보고 찾은 것이라 전달률 0.318 구간의 값(Public +0.001 수준)이고,
반대 신호는 실제 분포 쪽에서 나왔다. 양쪽 모두 1건짜리 차이라 잡음 수준이기도 하다.

## 6. 남은 길

v10의 누락 4건은 전부 **LLM이 품목을 못 집거나 두 호출이 엇갈리는 경우**이고, 후처리로 되살리면 오탐이 5배가 된다.
따라서 품목 식별 자체를 고쳐야 하며 이는 **프롬프트 수정 + 재추론**이 필요하다.
[2026-09-19 study log 1](./1.%20transfer_rate_two_regimes.md)의 계산대로 Public 0.70에는 v10·v11·v1·v24를 전부 0.85까지 올려야 한다.
