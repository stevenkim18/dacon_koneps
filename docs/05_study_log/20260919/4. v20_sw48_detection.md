# 2026-09-19 v20 — 좁혀야 할 것은 `is_software`가 아니라 대기업 참여제한 탐지였다

[study log 3](./3.%20cheap_rule_candidates_closed.md)에서 v20의 무라벨 250 정밀도가 0.50인 원인을 `is_software` 과탐으로 추정했다. **틀렸다.** dev 오탐을 원문에서 직접 확인하니 탐지 실패였다.

## 1. dev 유일한 v20 오탐 `PPS-DEV-064`의 원문

```
※ 소프트웨어진흥법 제48조에 따른 소프트웨어사업자의 사업금액별 참여 제한
```

공고가 대기업 참여제한을 **이미 명시하고 있다.** 라벨 0이 맞다.
현행 사실 추출은 `bool(re.search(r"대기업|상호출자제한|중견기업", 전체원문))`이라 "대기업"이라는 낱말이 없으면 못 잡는다. 이 공고에는 '대기업'이 **0번** 나온다.

근거 법령도 낱말이 아니라 '명시' 자체를 의무로 규정한다. `중소 소프트웨어사업자의 사업 참여 지원에 관한 지침` **제3조 ②**: "국가기관등의 장이 … 소프트웨어사업을 발주하는 경우 **입찰공고문 또는 제안요청서에 대기업 참여제한 하한제도 적용 여부(적용 근거 포함)를 명시하여야 한다.**"

`is_software`를 좁히는 방향은 반대로 근거가 없다. dev의 v20 양성 5건에는 **물품(내자)** 공고(`PPS-DEV-133`, 1.24억)가 들어 있고, SW진흥법 제2조 2·3호의 "소프트웨어사업"은 "소프트웨어산업과 관련된 경제활동"으로 넓게 정의된다. 업무구분으로 거를 수 없다.

## 2. 후보 R1 — 제48조 명시 줄 인식

같은 줄에 ① `소프트웨어` ② `(참여|참가) 제한` ③ `제48조(단 '제48조의2' 제외)|사업금액|제한금액|하한`이 모두 있고, 상투문 낱말(`보안|손해배상|부정당|청렴|금품|향응|계약보증금|하자보증`)이 없을 때만 명시로 인정한다.

세 조건을 모두 요구한 이유는 [2026-09-18의 교훈 4](../20260918/)(조문 번호만으로 법을 매칭하지 않는다)와 같다. 20,000건을 훑어 보면 단독 신호는 전부 상투문이다.

- `제48조` 단독 → 「조달청 내자구매업무처리규정」제48조의2(계약보증금), 지방계약법 시행령 제48조(추첨)
- `참여 제한` 단독 → 보안서약서 "보안사항을 위반할 경우 … 사업 참여 제한", 부정당업자 제재

**저장 출력 950건에서 이 규칙이 새로 잡는 공고는 정확히 2건이고 둘 다 의도한 문장이다.**

| 공고 | 문장 |
|---|---|
| PPS-DEV-064 | `※ 소프트웨어진흥법 제48조에 따른 소프트웨어사업자의 사업금액별 참여 제한` |
| PPS-D-013945 | `총 사업금액 20억원 미만인 사업으로, 중소 소프트웨어사업자(… '공공 소프트웨어사업 입찰참여 제한금액:없음'으로 확인)만 참가 가능` |

## 4. R2(부가세)를 기각한 근거 — 자가 라벨 2건 추가

`지침 제3조 ①3호`("사업금액은 … 추정가격에 부가가치세를 포함한 금액으로 한다")는 분명하고, 해당 2건의 `배정예산금액`이 추정가격×1.1과 정확히 일치해 산식도 데이터로 확인된다. 그런데 이 보정으로 새로 켜지는 무라벨 2건을 원문에서 읽어 보면 둘 다 위반으로 보기 어렵다. `labels/train250_audit.csv`에 근거를 적어 추가했다.

| 공고 | 라벨 | 근거 |
|---|---|---|
| PPS-D-014968 | 0 (medium) | 공고명 "기상-AI 부스트캠프 운영 대행 용역", 면허가 소프트웨어사업자(디지털콘텐츠개발서비스) **과** 국제회의기획업 동시 요구 — SW진흥법 제2조 2·3호의 소프트웨어 개발·운영 관련 경제활동이라기보다 교육·행사 운영 대행 |
| PPS-D-014146 | 0 (medium) | 물품 제조 **소액수의 견적제출 공고**(계약방법 수의계약) — 지침 제3조②의 명시 의무 대상은 "입찰공고문 또는 제안요청서"이고 법 제48조②는 입찰 참여 제한이라 문언이 닿지 않는다 |

둘 다 medium 신뢰도의 자가 라벨이다. **R2의 기각은 이 두 라벨에 기대고 있으므로, 라벨이 뒤집히면 R2도 다시 본다.** 부가세 보정 자체는 고시 원문 근거가 있어 폐기가 아니라 보류다.

## 5. 금액 상한은 걸지 않는다

`항목표.json`의 v20 비고는 "사업금액 기준 참여제한 다름 (20억 미만, 40억 미만, 80억 미만, 80억 이상)"이고, 지침 **별표 1**은 대기업이 참여할 수 있는 사업금액의 하한을 매출 8천억 이상 대기업 80억, 8천억 미만 40억, 중견기업 전환 5년 이내 20억으로 정한다. 80억 이상 사업이면 모든 대기업이 참여 가능하므로 상한을 걸 여지가 있다.

**걸지 않는다.** R1 적용 후 v20이 켜지는 177건의 사업금액(추정가격×1.1) 분포는 아래와 같다.

| 구간 | 건수 |
|---|---:|
| 1억~20억 | **168** |
| 20억~40억 | 5 |
| 40억~80억 | 3 |
| 80억 이상 | **1** |

95%가 모든 유형의 대기업이 제한되는 1억~20억 구간이다. 상한을 걸어야 달라지는 공고는 최대 1~4건으로 잡음 수준이고, dev에는 49.5억(`PPS-DEV-134`, 라벨 1)까지만 있어 검증할 근거도 없다. 지침 제3조②이 "적용 **여부**"의 명시를 요구하는 이상 80억 이상에서도 미적용 사실을 적어야 한다는 해석이 가능해, 어느 쪽도 데이터로 못 가른다.

## 6. 적용 방법

`regex_facts()`의 해당 줄을 다음으로 바꾸고 모듈 상단에 헬퍼를 추가한다. v20은 `ITEM_SOURCE`가 `rx`라 **LLM 재추론이 필요 없다.** v20은 `ABSENCE` 항목이라 근거 문구에도 영향이 없다.

```python
"대기업_참여제한_문구": bool(re.search(r"대기업|상호출자제한|중견기업", src)) or sw_big_limit_noted(src),
```

```python
SW_LIMIT_RE = re.compile(r"(참여|참가)\s*제한")
SW_LIMIT_HOOK_RE = re.compile(r"제\s*48\s*조(?!\s*의)|사업\s*금액|제한\s*금액|하한")
SW_LIMIT_NOISE_RE = re.compile(r"보안|손해배상|부정당|청렴|금품|향응|계약보증금|하자보증")


def sw_big_limit_noted(src: str) -> bool:
    for line in src.split("\n"):
        if "소프트웨어" not in line:
            continue
        if SW_LIMIT_RE.search(line) and SW_LIMIT_HOOK_RE.search(line) and not SW_LIMIT_NOISE_RE.search(line):
            return True
    return False
```
