# 2026-09-19 오답은 항목이 아니라 공고에 뭉쳐 있다 — meta 증언으로 품목 되살리기

## 1. 오답 50건은 공고 36건에 들어 있다

[study log 4](./4.%20v20_sw48_detection.md)의 R1 기준으로 dev 오답을 항목이 아니라 **공고 단위**로 묶었다.

| 공고 | 오답 수 | 내용 |
|---|---:|---|
| PPS-DEV-061 | **4** | FN v6, FN v10, FN v11, FP v18 |
| PPS-DEV-062 | 3 | FN v10, FN v11, FN v24(재현불가) |
| PPS-DEV-03 / 048 / 051 / 064 / 065 / 075 / 119 / 165 / 191 | 각 2 | — |
| 나머지 25건 | 각 1 | — |

Macro F1은 항목별 평균이므로 **한 공고를 고치면 여러 항목이 동시에 오른다.** DEV-061 하나가 4개 항목에 걸려 있다.

## 2. DEV-061의 원인은 meta에 적혀 있었다

```
meta.조항호내용        : 중소벤처기업부장관이 지정 공고한 물품
meta.면허업종제한목록   : [기타자유업(행사대행업)(9901)]
본 호출 품목           : 해당없음
전용 호출 품목         : 9015189001 (축제기획및대행서비스)
```

발주기관이 meta에 **"이 계약의 목적물은 중기부장관이 지정 공고한 물품"**이라고 적어 놓았는데(판로지원법 제6조·제7조의 경쟁제품 지정), 본 호출만 품목을 못 골라 `해당없음`이 되고 그 결과 v10·v11이 죽고 v18이 잘못 켜졌다.

dev에서 이 기재가 있는 공고는 11건이고 **10건은 이미 `comp=True`**다. 즉 이 신호는 판정을 뒤집는 게 아니라 탐지 실패를 메운다.

같은 자리에서 두 번째 신호도 나왔다. DEV-061·062·075와 무라벨 PPS-D-008554는 전부 **면허업종에 `기타자유업(행사대행업)(9901)`**이 있다. 발주기관이 행사대행업 등록을 요구했다는 것은 목적물이 행사·전시·축제 대행이라는 뜻이고, 그 품명들은 경쟁제품 목록의 `전시회,회의및행사대행서비스`·`축제` 그룹에 있다.

## 3. 후보 C3

`decide()`에서 품목 코드가 `해당없음`으로 정해졌을 때만, meta가 목적물 성격을 증언하고 전용 호출의 코드가 경쟁제품표에 있으면 그 코드를 쓴다.

```python
if code == "해당없음" and (meta_designated_competitive(rec) or meta_event_license(rec)) \
        and table.get(str(item["세부품명번호"])):
    code = str(item["세부품명번호"])
```

2026-09-19 오전에 기각한 [융합 변형 B](./2.%20v10_item_fusion_variants.md)("본 호출이 해당없음이면 전용 호출 코드를 쓴다")와 모양은 같지만 **게이트가 있다.** B는 v10 오탐을 3 → 16건으로 늘렸다. C3은 dev 오탐을 **한 건도 늘리지 않는다**(v10 FP 3 유지, v11 FP 1 유지).

| 지표 | 기준 | R1 | **R1+C3** |
|---|---:|---:|---:|
| dev 200 | 0.8366 | 0.8403 | **0.8610** |
| 교차 검증 | 0.8075 | 0.8117 | **0.8281** |
| v10 | 0.462 (3/3/4) | 0.462 | **0.667 (5/3/2)** |
| v11 | 0.600 (3/1/3) | 0.600 | **0.833 (5/1/1)** |
| v18 | 0.800 (6/2/1) | 0.800 | **0.857 (6/1/1)** |
| 무라벨 250 정밀도 | 0.765 | 0.765 | 0.765 |

무라벨 750건에서 바뀌는 공고는 `PPS-D-008554` 1건(v12 1→0, v17 1→0)뿐이고, 원문이 "판로지원법 제9조 … 아래의 세부품명의 직접생산확인증명서를 모두 소지한 자"를 요구하고 meta가 "중소기업청장이 지정.고시한 제품"이라 **둘 다 오탐 제거가 맞다.** `labels/train500_audit.csv`에 근거와 함께 기록했다.

무라벨 20,000건 기준 사정권: 조항호내용 지정 문구 329건(1.65%), 행사대행업 면허 452건(2.26%). 실제로 코드가 바뀌는 비율은 표본에서 0.13~1%다.

## 7. v24 — 고친 것은 허용오차가 아니라 "어떤 금액을 비교하는가"였다

v24 4축(예산·업종·지역·제목)의 기여를 dev에서 갈라 보면 **어느 축도 버릴 수 없다.**

| 축 | 정탐 | 오탐 |
|---|---:|---:|
| 예산 | 1 | 1 |
| 업종 | 1 | 0 |
| 지역 | 1 | 1 |
| 제목(계약방법·금액구간) | 2 | 0 |

지역 축을 빼면 교차검증 0.8281 → 0.8245로 떨어진다(정탐도 같이 잃는다).

예산 축의 오탐·정탐을 원문에서 비교하니 차이는 금액의 **크기**가 아니라 **이름**이었다.

| 공고 | 라벨 | 공고서 금액 | meta 배정 | 그 금액이 적힌 이름 |
|---|---|---:|---:|---|
| PPS-DEV-29 | **1** | 37,930,000 | 39,730,000 | **기초금액** (+ 용역금액) |
| PPS-DEV-044 | **0** | 61,560,000 | 61,000,000 | 사업예산 / 과업예산 |
| PPS-D-008128 (무라벨) | — | 446,000,000 | 446,600,000 | **기초금액** (+ 사업금액) |

`기초금액`은 공고가 공식적으로 고지하는 금액이라 나라장터 입력값과 달라지면 기재 오류지만, `사업예산·과업예산`은 발주부서 내부 표기라 배정예산과 달라도 위반이 아니다. 그래서 **비교 자체를 공식 고지 금액 줄로 한정**했다(W1).

처음에는 허용오차를 0.1% → 1~2%로 올리는 변형(V1)을 만들었다. dev 결과는 W1과 똑같지만(v24 0.667 → 0.714, 교차검증 0.8301) **무라벨에서 갈렸다.** V1은 `PPS-D-008128`의 0.13% 차이를 잡음으로 보고 꺼 버리는데, 그 공고는 기초금액을 두 번 고지한 진짜 불일치다. W1은 이 건을 양성으로 유지하면서 대신 `PPS-D-006618`(이름 없는 숫자 23,943,340원, 배정예산과 31.9% 차이)만 끈다. **dev만 봤으면 둘을 구분할 수 없었다.**

## 8. 같은 방식으로 시도했다가 기각한 v1

운영진은 v1에 "법령상 근거 없는 시설·인력 보유 제한"이 포함된다고 답했고, dev DEV-063에 실물이 있다 — "「경비업법」 제4조에 따른 시설경비업을 등록하고 **50명 이상의 보안인력을 보유한 업체**"(라벨 1).

정량 보유 제한 정규식(`\d+\s*(명|인|개소|개|대|톤)\s*이상 … (보유|갖춘|확보)`)을 참가자격 문맥에 걸어 dev를 훑으면 **5건이 걸리는데 v1 양성은 1건뿐이다.**

| 공고 | v1 | 문장 |
|---|---:|---|
| DEV-063 | **1** | 50명 이상의 보안인력을 보유한 업체 |
| DEV-27 | 0 | 산림교육전문가(숲해설가)를 2명 이상 보유 |
| DEV-083 | 0 | 계약상대자 소유 15톤 이상 암롤차량 보유한 업체 |
| DEV-167 | 0 | 연락책임자 1명 이상 포함 확보 가능한 업체 |
| DEV-175 | 0 | 살수차(16톤) 3대 이상 보유한 업체 |

정밀도 0.20. 가르는 기준은 수량이 아니라 **과업상 필요성·관련성**이고, 그것은 판단이지 정규식이 아니다(우리 FP인 DEV-101의 'DEWESOFT 계측 기술 보유 제한'도 라벨 0이다). v1은 **본 호출 프롬프트 수정 + 재추론** 없이는 못 고친다.

v12도 같은 결론이다. `직생요구 ∧ ¬comp` 구조에서 `¬comp`의 대부분이 "품목을 못 찾음"인데, dev v12 정탐 6건 중 5건이 바로 그 '해당없음' 상태라 "찾았는데 경쟁제품 아님"으로 조건을 바꾸면 정탐이 무너진다.
