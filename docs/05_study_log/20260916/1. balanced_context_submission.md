# 두 번째 제출: balanced context 결과

## 1. 실험 질문

공식 베이스라인에서 거의 전부 빠지는 첨부문서와 공고문 후반을 더 많이 제공하면 Public F1이 올라가는가?

## 2. 실행 전 예상

- dev 정답 근거 54개 중 입력에 남는 수가 47개에서 54개로 증가했다.
- 무라벨 20,000건에서 첨부가 입력되는 공고가 146건에서 15,276건으로 증가했다.
- 첨부 의존성이 큰 v9·v22·v23과 실적제한 항목의 판단이 개선될 것으로 예상했다.

이 예상은 모델 없는 입력 보존 검사에 기반했다. 실제 Gemma dev 추론과 항목별 F1은 확인하지 못했다.

## 3. 변경 사항

첫 제출의 공식 베이스라인에서 다음을 변경했다.

1. 문서 예산을 4,000자에서 8,000자로 확대
2. 공고문 선두 약 4,000자를 유지하고 공고문 후반과 첨부에 나머지 예산 배분
3. 문서 시작·끝과 후보 문구 주변 발췌
4. 영문·숫자 제품 코드 주변 발췌
5. 항목표의 국가·지방 법령 근거를 시스템 프롬프트에 추가
6. 불완전한 관측에서 부재탐지를 보수적으로 0으로 처리하도록 지시
7. v22·v23·v24의 적용 조건을 명시

## 5. 예상과 다른 점

입력 보존 지표는 모두 개선됐지만 실제 F1은 하락했다.

| 모델 없는 대리 지표 | 첫 제출 | 두 번째 제출 |
|---|---:|---:|
| dev 제공 근거 보존 | 47/54 | 54/54 |
| 첨부가 입력된 무라벨 공고 | 146/15,276 | 15,276/15,276 |
| 실적제한 후보 문구 잔존율 | 21.5% | 85.6% |
| 모델·상표 후보 문구 잔존율 | 11.3% | 87.4% |

이 결과로 다음을 확인했다.

- 근거가 입력에 존재하는 것은 올바른 판정의 필요조건일 수 있지만 충분조건은 아니다.
- 더 긴 입력은 유용한 정보뿐 아니라 무관한 문장과 상충하는 표현도 늘린다.
- 근거 보존율을 F1의 직접적인 대리 지표로 사용하면 안 된다.
- Macro F1은 양성 클래스의 정밀도와 재현율을 함께 보므로, 불확실하면 0으로 두는 지시가 재현율을 떨어뜨릴 수 있다.

## 6. 실패 원인 가설

아래는 총점과 코드 차이에서 세운 가설이며 항목별 정답이 없으므로 확정된 원인이 아니다.

1. 8,000자 입력으로 판단 대상이 희석됐다.
2. 여러 발췌문을 이어 붙여 조건과 예외의 문맥이 끊겼다.
3. 조문명만 추가해 프롬프트 길이와 복잡도만 증가했다.
4. 부재탐지 보수 지시가 양성 예측을 과도하게 줄였다.
5. 여러 요소를 동시에 변경하여 원인 분리가 불가능해졌다.

## 7. 결정

- 이번 `balanced context` 제출은 채택하지 않는다.
- 첫 제출의 공식 베이스라인과 점수 `0.2149545622`를 안정 기준으로 유지한다.
- 다음 실험부터 한 번에 한 가지 요소만 변경한다.
- 실제 Gemma dev 추론을 실행할 수 없는 동안에는 모델 없는 대리 지표가 좋아졌다는 이유만으로 성능 향상을 확정하지 않는다.

## 8. 다음 실험

첫 제출 코드를 그대로 시작점으로 사용한다.

변경 후보 하나:

- 원래 시스템 프롬프트 유지
- 원래 공고문 4,000자 유지
- 법령명 추가와 보수적 0 지시 제거
- 첨부 의존 항목을 위한 짧은 첨부 발췌 약 1,000자만 추가
- 전체 입력은 약 5,000자로 제한

이 실험에서는 첨부 발췌 이외의 설정을 바꾸지 않아 효과를 분리한다.

## 9. 한 문장으로 배운 점

모델에게 더 많은 원문을 보여 주는 것보다, 현재 판단에 필요한 짧고 연결된 문맥만 제공하는 것이 중요하며 대리 지표와 실제 F1은 반드시 따로 검증해야 한다.
