# 2026-09-22 토크 게시판 재확인

## 새 운영 답변: 오타 처리

운영진은 [오타 처리 질문](https://dacon.io/competitions/official/236754/talkboard/417766)에 다음 기준을 확정했다.

1. 문서에 오타가 있다는 사실 자체는 별도 위반 항목이 아니다.
2. 실제 공고문·첨부문서의 문구와 주변 문맥으로 항목을 판정한다.
3. 문맥 이해를 위한 띄어쓰기·명백한 오탈자의 내부 정규화는 허용된다.
4. 외부 원문을 찾아 복원하거나 보충하면 외부 데이터 사용 및 익명화 식별자 복원 금지에 걸린다.
5. 금액·지역·업종·자격처럼 판정에 직접 영향을 주는 값은 오타인지 불확실하면 임의 보정하지 않는다.
6. 평가 데이터에도 오타가 없다고 전제할 수 없다.
7. 근거문구는 정규화한 문장이 아니라 제공된 `docs.text`에 실제 존재하는 부분문자열이어야 한다.

## 현재 코드와의 대조

현재 최고 제출은 `submissions/20260922_focused_calls`(Public **0.687531013**)이고 다음 후보는 `submissions/20260923_v22_region_fix`다.

| 확인 항목 | 상태 | 판단 |
|---|---|---|
| 근거문구 원문 부분문자열 검사 | `clean_evidence()`가 후보 문자열이 원문에 존재하는지 검사한다. | 새 답변과 일치한다. |
| 오타를 별도 위반으로 판정 | 그런 규칙이 없다. | 변경 불필요. |
| 정규화 후 근거 제출 위험 | 정규식과 LLM이 문맥을 읽더라도 최종 근거는 원문 검사에서 걸러진다. | 현재 안전장치를 유지한다. |
| 평가 데이터 오타 가능성 | 프롬프트와 정규식이 완전 일치에만 의존하는 곳은 놓칠 수 있다. | 새 대규모 정규화 규칙을 바로 넣지 말고 실제 누락 사례가 확인된 항목만 분리 실험한다. |

이번 답변은 현재 후보를 즉시 바꿀 근거라기보다 **전처리와 근거 생성의 경계를 확정**한다. 정규화된 문자열을 근거로 직접 출력하지 않는 현재 구조는 맞다.

## 새 질문 두 건: 아직 규칙으로 쓰지 않음

### v20 `정보화사업여부`

[새 질문](https://dacon.io/competitions/official/236754/talkboard/417849)은 dev 200건에서 `meta.정보화사업여부`가 모두 `미입력`인데 평가 데이터도 같은지, SW 사업 여부를 본문으로만 판단해야 하는지 묻는다. 2026-09-22 확인 시 본문 댓글 영역에는 운영진 답변이 없다.

현재 후보는 이 필드에 의존하지 않고 공고 제목·본문·SW 관련 문구로 `is_software()`를 계산한다. 답변이 오기 전까지 `미입력`을 비SW로 해석하거나 평가 데이터 분포를 추정하지 않는다.

### v5 지방 고시금액

[새 질문](https://dacon.io/competitions/official/236754/talkboard/417853)은 배포 법령에 구체적 국제입찰 대상 금액이 없는데 외부 고시의 3억 5천만 원을 정적 규칙으로 써도 되는지, DEV-11의 v5=0을 제공 자료만으로 어떻게 재현하는지 묻는다. 아직 댓글이 없다.

현재 후보는 일반 지방 물품·용역의 v5 경계를 `LOCAL_REGION_AMOUNT = 500_000_000`으로 둔다. 참가자가 제시한 3억 5천만 원은 운영진 확정 기준이 아니므로 지금 바꾸지 않는다. 답변이 오면 다음을 확인한다.

- 외부 고시 금액의 제출물 사용 허용 여부
- 공고 시점별 고시 금액을 고정 상수 하나로 써도 되는지
- DEV-11을 제공 자료만으로 재현할 수 있는지, 아니면 라벨 노이즈인지
- 일반 용역과 건설기술·안전점검 용역의 금액 구분에 변화가 필요한지
